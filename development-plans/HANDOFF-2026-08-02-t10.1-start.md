## Owner rulings

All binding; none is implemented in forge code yet.

- **The consumer/operator operating model** (2026-08-02). Operators
  (sax-datastores, sax-temporal) own infrastructure strategy, configuration,
  and operation; consumers (forge, pbook, ocr) request through committed
  registrations and tickets. Consumers never edit operator repos and never
  superuser into shared instances. The permission sandbox that blocks an
  agent from doing so is a feature, not an obstacle to route around.
- **No product DDL, ever** (issue #2, P2/P5). Schema changes are authored in
  forge as Alembic revisions — one revision per phase — generated as offline
  SQL (`alembic upgrade <n-1>:<n> --sql`, per-phase stamps kept,
  `BEGIN`/`COMMIT` stripped), committed under
  `datastore-changes/<id>-<title>/`, and requested by an issue on
  sax-datastores. **The commit is the request; a new commit voids approval.**
  The administrator applies. Agents on either side never do.
- **Verify-only startup lands by agreement now**, not later when §21's
  privilege split forces it: all three workers replace `run_migrations` at
  startup with a version check that fails closed with a named "schema
  behind" error.
- **Expand/contract is binding.** Every request must leave
  currently-deployed code working; a breaking change is three requests. To
  be written into PROCESS.md/SDLC.md so it binds future change-sets.
- **§21 direction — credential consolidation.** `prod_ddl` / `prod_app` /
  `prod_ro` / `dev_user`; no product DDL; roughly two prod product databases,
  with **forge's placement still open pending T6.8**. The DB-URL suffix
  guard's redesign moves to this landing, superseding T10.1's earlier
  "cutover change-set" placement.
- **§22 is categorical — no agent container self-provisioning.** The
  sanctioned agent test path is `forge_test`/`pbook_test` on the dev stack
  via `pg_hba` `trust` (no credential material exists at all). The three
  other `_test` roles drop at §21. Forge repoints its conftests only after
  the operator announces the pg_hba smoke test on issue #2; an unreachable
  test database becomes a **named error, not a skip**.
- **R8 (reverse channel — operator-initiated notices to consumers) and R9
  (dev self-service for a product's own databases) granted.** R8 also
  carries advance notice: unprefixed tables in a shared database will be
  rejected, so forge's `runs` / `interactions` / `batch_jobs` rename to
  `forge_*` eventually — sequenced after T6.8 resolves `playbooks`
