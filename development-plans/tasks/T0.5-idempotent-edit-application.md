## Problem

1. **Double application under retry.** `write_output` applies edits
   file-by-file, writing each to disk inside the loop
   (`activities/output.py:459-474`). `_WRITE_RETRY`
   (`workflows.py:128-131`) retries the whole activity on transient
   `OSError`, so files edited before the failure are re-read and
   re-edited on retry. Reproduced: an insert-style edit (replace contains
   search) applied twice silently duplicates the inserted line; a plain
   replace re-applied raises non-retryable `EditApplicationError`,
   failing the workflow after paid LLM calls. Ordinary disk pressure
   converts a recoverable transient into silent file corruption that
   flows into validation and commit.
2. **Raw-string mutual-exclusion guard.** The files/edits overlap check
   intersects raw LLM-supplied path strings (`output.py:448-453`) while
   both resolvers call `.resolve()` — so `a.py` vs `./a.py` (or
   `sub/../a.py`) bypasses the invariant; because new files are written
   before edits are resolved (`:459-474`), the edit then passes
   `resolve_edit_paths`' `is_file()` check against the just-created file
   and is applied on top of freshly generated content.

## Scope

- Compute all edited contents in memory before the first disk write; on
  retry, detect already-applied edits (search absent but replace present
  → idempotent skip) instead of re-applying or raising.
- Compare resolved paths in the files/edits mutual-exclusion guard (the
  resolvers already compute them); note that resolved-path comparison
  alone still misses APFS case variants.
- Property-based (hypothesis) tests over the pure matching/application
  functions — the textbook property target per test-strategy.md:67
  (cross-noted in T5.5; whichever lands first owns them).

## Plan

Both defects live in `write_output` (`src/forge/activities/output.py`), which
writes new files and applies edits file-by-file *inside two loops*, interleaving
disk writes with reads/apply. The fix is a **stage-then-write refactor** plus an
**idempotent-skip** in the pure edit application:

1. **Stage everything before the first disk write.** Resolve all new-file paths
   and all edit paths (traversal + `is_file` checks) up front, compute every
   final content in memory (read each edit target, apply its edits), and only
   then write. A failure (transient `OSError`) during the write phase leaves the
   worktree either untouched (if it fails before reaching a file) or partially
   written — and the retry re-reads and recomputes from disk, applying edits
   idempotently.
2. **Idempotent-skip (defect 1).** Add `_edit_already_applied(content, search,
   replace)` and thread an `idempotent` flag through `apply_edits` /
   `apply_edits_detailed` (default `False`, so every existing call is
   byte-identical; `write_output` opts in with `idempotent=True`). Rule:
   - insert-style (`search in replace`): already-applied iff `replace in content`;
   - plain replace: already-applied iff `search not in content and replace in content`.
   Skipped edits produce no `match_results` entry. Residual ambiguity documented
   in the helper docstring (insert first-application where the file already holds
   the verbatim replacement; delete edit with an absent search).
3. **Resolved-path mutual-exclusion (defect 2).** Compute the files/edits overlap
   on the *resolved* `Path` values (the resolvers already `.resolve()`), before
   any write — closing the `a.py` vs `./a.py` / `sub/../a.py` bypass. Keep the
   "both files and edits" message shape. Document the APFS case-insensitivity
   residual (`A.py` vs `a.py` resolve distinct but name one file) in a comment.

Only `src/forge/activities/output.py` changes; `MatchLevel` (in `models.py`, out
of scope) is untouched, so skips are represented by omission from `match_results`
rather than a new enum member.

## Development Notes

**2026-07-18** — Implemented per plan.

- **Blast radius check.** `apply_edits`/`apply_edits_detailed` are consumed only
  by `write_output` (src) and tests; `match_results`/`EditMatchResult`/
  `MatchLevel` are asserted only in tests, never read by production code — so
  omitting a `match_results` entry for a skipped edit breaks nothing, and no new
  `MatchLevel` member is needed (which mattered, since `models.py` is out of the
  T0.5 boundary).
- **`idempotent` defaults `False`.** Keeps all pre-existing pure-function tests
  byte-identical; `write_output` is the sole opt-in caller. It is also the only
  edit-application path in the codebase (conflict resolution writes via
  `write_files`, dict-based, not edits).
- **Idempotent-skip runs *before* the match chain**, so when it returns `False`
  the exact→whitespace→indentation→fuzzy behavior is unchanged. The plain-replace
  rule's `replace in content` half is deliberate: it keeps a genuine typo
  (`search not found`) raising instead of silently skipping. The one exception is
  a delete edit (`replace == ""`): `replace in content` is trivially true, so the
  rule reduces to "search absent" and a completed delete is skipped on retry —
  correct for idempotency, but it cannot distinguish an already-applied delete
  from a delete whose search never matched. Documented in the helper docstring.
- **Insert-case residual ambiguity.** For `search in replace`, a legitimate
  *first* application whose target file already contains the verbatim replacement
  block is indistinguishable from an already-applied retry and would be
  false-skipped. Requires the file to already hold the exact replacement — rare
  for a genuine insert. Documented.
- **Defect-2 ordering.** `resolve_edit_paths` (with its `is_file` gate) runs
  before the overlap check, so for a *non*-pre-existing target the "does not
  exist" error fires first; for a pre-existing target the resolved-overlap guard
  fires. Both reject before any write, so AC2 holds either way; the AC2 test
  pre-creates the file to exercise the resolved-overlap guard specifically and
  asserts the file's bytes are unchanged.
- **Tests.** AC1 (regression) + AC2 (path-spelling) added to
  `tests/test_activity_output.py`; AC3 property tests in the new
  `tests/test_output_properties.py` (6 hypothesis properties: insert-style and
  plain idempotency, exact-match surgery, whitespace-vs-exact agreement, exact
  span end-to-end, empty-search invariant — tight disjoint-alphabet generators,
  no marker → default suite). Also added deterministic `TestEditAlreadyApplied`
  (truth table) and `TestIdempotentSkip` (incl. a `default_is_not_idempotent`
  guard proving the flag gates behavior). A fuzzy-agreement property was
  deliberately omitted: `_fuzzy_match` raises on near-ties, which makes such a
  property health-check-fragile; whitespace agreement + exact-span cover the
  "strategies agree on unperturbed content" intent without that fragility.
