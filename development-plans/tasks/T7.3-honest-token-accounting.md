# T7.3 — Honest token accounting

**Status:** NOT STARTED
**Phase:** 7 — Context engine (forge)
**Repos:** forge
**Depends on:** [T7.1](T7.1-project-descriptor.md)
**Last updated:** 2026-06-10

## Problem

Context packing budgets tokens with an uncalibrated chars-per-token
guess, and the configured `token_budget` is applied as-is, with no
awareness of the model window, the prompt scaffolding around the packed
items, or the reserve needed for the model's output. Packing can
therefore overshoot what the call can actually carry — and retries make
it worse, because error sections grow the scaffolding while the budget
stays fixed. The merged plan carries Plan A's Phase 7 fix: a calibrated
estimator plus `effective_budget` arithmetic (D33 amendment).

## Background and Detailed Explanation

Before forge sends a task to the model, it *packs* context — selecting
files and summaries and fitting them under a token budget. Two things
about that budget are dishonest today. First, tokens are estimated with
an uncalibrated 4-characters-per-token constant (D33). Second, the
configured `token_budget` is used as-is: nothing subtracts the model's
context window, the fixed prompt *scaffolding* wrapped around the packed
items (role, instructions, output requirements), or the *output reserve*
the model needs to write its answer. So packing can fill a budget the
actual call cannot carry, and the call overflows.

**Retries make it worse.** A retry adds an error section describing the
prior failure — which grows the scaffolding — while the budget stays
fixed. Each retry pushes closer to the ceiling at exactly the moment
more text is being added.

**The fix.** Inject a calibrated chars-per-token estimate (~3.4 for
code) as a parameter on `build_context_items`/`pack_context` instead of
the hardcoded constant, and compute a real ceiling per task:
`effective_budget = min(token_budget, model_window − scaffolding −
output_reserve)`. Re-estimate the scaffolding on every retry so the
packed content shrinks to make room for the growing error section rather
than blowing past the window. The point is not exact tokenization — it
is overflow prevention that stays honest as the prompt changes. Done
means `output_reserve` is provably live: a test where raising the
reserve shrinks what gets packed (D96 amends D33).

## Scope

- Calibrated chars-per-token (~3.4 for code) injected as an estimator
  parameter on build_context_items/pack_context.
- `effective_budget = min(token_budget, model_window − scaffolding −
  output_reserve)` per task, scaffolding re-estimated on retries (error
  sections grow).
- D33 amendment.
