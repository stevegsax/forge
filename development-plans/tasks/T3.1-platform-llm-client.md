## Problem

Output shaping today uses forced tool use via sax-llm's provider stack and
a string-keyed registry. The review verified that structured outputs are
GA, work in the Message Batches API, and compose with prompt caching — so
forced tool use can retire. `messages.parse` is sync-only, which means the
platform library must own **both** lanes: a sync client and the batch
request-body builder + helpers that Plan B's design forgot (forge is
batch-first).

## Scope

`sax_platform.llm`: `AnthropicLLM(client)` with
`complete[T: BaseModel](..., output_type: type[T]) -> Completion[T]` on
`client.messages.parse`, `complete_schema(...)` (JSON-schema dict path),
`complete_text(...)`; frozen `Completion[T]` with token/cache telemetry;
**plus the batch lane Plan B forgot**: pure batch request-body builder
(model, system, messages, `output_config.format` schema → request dict),
batch submit/status/results helpers. Verified: structured outputs are GA,
work in the Batch API, compose with caching (use 1h-TTL cache_control in
batches; hits are best-effort 30–98%).

### Amendments (2026-07-08)

The client must own the failure surface, not just the happy path:

- Construct provider clients with `max_retries=0` — retries belong to
  Temporal's activity RetryPolicy (port the rationale from the dead
  `forge/llm_client.py:258-264`; see T1.1's amendment).
- Surface `stop_reason` on both lanes as typed outcomes: refusal,
  `max_tokens` truncation, and text-only responses must be distinguishable
  from schema-validation failures. Today all three collapse into misleading
  ValidationErrors; on the batch lane the parse then retries
  deterministically on identical stored bytes after a paid up-to-24h
  round-trip.
- Per-call output-token budget: no hard 4096 default. Call sites must be
  able to size `max_tokens`; generation prompts demand complete file
  contents that routinely exceed 4096 output tokens.
