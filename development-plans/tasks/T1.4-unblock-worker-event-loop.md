# T1.4 — Unblock the worker event loop

**Status:** DONE
**Phase:** 1 — Stop the bleeding (current repos)
**Repos:** forge
**Depends on:** —
**Last updated:** 2026-07-08

## Problem

Blocking `subprocess.run` + file I/O inside async activities freezes workflow
task processing and defeats heartbeats (validate.py `_run_command`, git.py via
git_activities, providers.py run_tests/ruff/git handlers, code_intel
discovery).

## Scope

- Route every such call through `await asyncio.to_thread(...)`.
- Restore `_VALIDATE_HEARTBEAT` to 60s as a real crash detector.

### Amendments (2026-07-08, capture sweep)

- While rewriting `validate.py`'s `_run_command`, catch
  `subprocess.TimeoutExpired` and convert it to a failed
  `ValidationResult` (check name preserved, "timed out after Ns") instead
  of letting it crash the activity — today a >60s test suite fails the
  workflow after LLM spend rather than feeding the error-aware retry loop
  (`validate.py:35-52,121-127`; providers.py already catches it at four
  sites). Make the test-check timeout configurable with a realistic
  default aligned to `_VALIDATE_TIMEOUT`, not the flat 60s.
- Add `handle_search_code` to scope: it compiles and runs an LLM-supplied
  regex per line with no timeout (`providers.py:67,90-91`), and
  `asyncio.to_thread` does NOT contain GIL-holding regex backtracking —
  the to_thread remedy alone is insufficient for this handler. Replace
  with a bounded search (delegate to `rg` under
  `SUBPROCESS_TIMEOUT_SECONDS`, or enforce a match timeout).

## Acceptance Criteria

## Plan

Boundary strategy (Function Core / Imperative Shell): the sync worker
functions stay sync; the `async def` activities quarantine the blocking work
behind `await asyncio.to_thread(...)`. This keeps the diff off the subprocess
internals (clean seam for T1.7, which owns the env dict).

Call sites routed through `asyncio.to_thread`:

1. **validate.py** (`validate_output` activity) — wrap each `_run_ruff_lint_fix`,
   `_run_ruff_format_fix`, `_run_ruff_lint`, `_run_ruff_format_check`,
   `_run_tests` call. This is what lets the `heartbeat_during` loop actually
   fire while a subprocess runs.
2. **git_activities.py** — wrap `create_worktree` / `remove_worktree` /
   `commit_changes` / `reset_worktree` (each ultimately shells out via
   `_run_git`).
3. **exploration.py** (`fulfill_context_requests` activity) — wrap the whole
   `fulfill_requests` dispatch; covers every provider handler (subprocess,
   grimp, file reads) in one boundary.
4. **context.py** (`assemble_context` / `assemble_step_context` /
   `assemble_sub_task_context`) — wrap the three `_discover_packed_context`
   calls; that is the code_intel discovery hotspot (grimp import graph + many
   file reads, repo-proportional).

Amendment work:

- Restore `_VALIDATE_HEARTBEAT` to 60s in workflows.py (it was 120s only to
  paper over the blocked event loop; now heartbeats fire every 30s inside the
  thread-offloaded run, so 60s is a real crash detector). Refresh the comment.
- validate.py `_run_command` timeout: add a shared `_run_check` that catches
  `subprocess.TimeoutExpired` and returns a failed `ValidationResult`
  (check name preserved, "… timed out after Ns"). Add
  `ValidationConfig.test_timeout_seconds` (configurable), defaulting to a new
  `TEST_TIMEOUT_SECONDS` aligned to `_VALIDATE_TIMEOUT` (2 min) rather than the
  flat 60s ruff cap.
- providers.py `handle_search_code`: replace the per-line Python `re` scan
  (GIL-holding catastrophic backtracking; `to_thread` does NOT fix that) with a
  bounded `rg` subprocess under `SUBPROCESS_TIMEOUT_SECONDS`. Rust regex is
  linear by construction and invalid patterns fail cleanly.

Scoping decision (documented in Development Notes): file reads/writes that are
bounded by the LLM output or an explicit file list (output.py writes,
context.py `_read_context_files`, planner/conflict reads, tiny metadata reads)
are left as-is — they are neither subprocess nor repo-proportional.

## Development Notes

- 2026-07-08 — Amended per the capture sweep
  ([forge-review-2026-07-08.md](../../forge-review-2026-07-08.md) §4.8,
  findings G3/G5): both defects live in the exact functions this task
  rewrites; fixing them separately would touch the same lines twice.

- 2026-07-15 — Implemented. Result: 1212 passed / 4 deselected, coverage
  87.90% (gate 85%), ruff clean apart from the two pre-existing
  `tests/test_worker.py` findings (TC003, SIM117) left per task instruction.

- **Boundary choice.** Wrapped blocking work at the `async def` activity
  boundary via `await asyncio.to_thread(...)`; the sync worker functions stay
  sync. This keeps the diff off the `subprocess.run(...)` internals, so T1.7
  (env dict) has a clean seam. Sites converted:
  - `validate.py::validate_output` → the five `_run_ruff_lint_fix`,
    `_run_ruff_format_fix`, `_run_ruff_lint`, `_run_ruff_format_check`,
    `_run_tests` calls.
  - `git_activities.py` → `create_worktree`, `remove_worktree`,
    `commit_changes`, `reset_worktree`.
  - `exploration.py::fulfill_context_requests` → the whole `fulfill_requests`
    dispatch (covers every provider handler in one boundary).
  - `context.py::{_assemble_context_inner, assemble_step_context,
    assemble_sub_task_context}` → the three `_discover_packed_context` calls
    (grimp import-graph + repo-proportional file reads).

- **Heartbeat constant.** `_VALIDATE_HEARTBEAT` was 120s purely to survive a
  blocked event loop. With validation offloaded to a thread the
  `heartbeat_during` loop fires every 30s, so restored it to 60s (a real crash
  detector: >2× the emit interval, <2× the `_VALIDATE_TIMEOUT` = 2 min
  start_to_close) and refreshed the stale comment.

- **Timeout → ValidationResult.** Added `_run_check(check_name, args, cwd,
  timeout)` which catches `subprocess.TimeoutExpired` and returns
  `ValidationResult(passed=False, summary="<check> timed out after Ns")` —
  mirroring providers.py's four existing catch sites. All three check helpers
  route through it. Fix-phase helpers (`_run_ruff_lint_fix`/`_format_fix`) were
  left with their original bodies (bounded ruff runs on the changed files, 60s
  cap) — only their call sites gained `to_thread`.

- **Configurable test timeout.** Added `ValidationConfig.test_timeout_seconds`
  (default None → module `TEST_TIMEOUT_SECONDS = 110`, aligned under the 120s
  `_VALIDATE_TIMEOUT` so the subprocess dies and yields a failed check before
  the activity itself times out). Ruff checks keep the fast 60s
  `SUBPROCESS_TIMEOUT_SECONDS`.

- **search_code → rg.** Replaced the per-line Python `re` scan (GIL-holding
  catastrophic backtracking; `to_thread` does NOT fix that) with a bounded `rg`
  subprocess under `SUBPROCESS_TIMEOUT_SECONDS` (30s). Behavior contract
  preserved: rg does not follow symlinks (matches stay in-worktree), exit 1 →
  "No matches", exit 2 → "Invalid regex pattern: …". Gotcha: when the candidate
  set is empty (only symlinks/ignored files) rg exits **2** with "No files were
  searched", not 1 — classified as no-matches so the symlink-escape test stays
  green. Dropped the now-unused `import re`. Also catch `FileNotFoundError` so a
  missing rg degrades to an error string instead of crashing the activity.

- **DEPLOY REQUIREMENT (rg not provisioned).** The EC2 host (Amazon Linux 2023)
  installs only `git`/`docker`/`awscli` via `dnf`
  (`deploy/scripts/bootstrap-instance.sh:28`,
  `deploy/terraform/user_data.sh.tftpl:8`). `ripgrep` is **not** installed, so
  the `search_code` provider will return "ripgrep (rg) is not installed" in
  production until `ripgrep` is added to the `dnf install` line. Not fixed here
  (out of this task's forge-only scope); flagged for the deploy owner.

- **Scoping (left as-is, documented).** File reads/writes bounded by LLM output
  or an explicit file list — `output.py::{write_output, write_files}` (generated
  files), `context.py::_read_context_files`, `planner.py`/`conflict_resolution`
  source reads, and tiny metadata reads (`_read_project_instructions`) — are
  neither subprocess nor repo-proportional, so per the task's judgment rule they
  were not wrapped.

- **Test approach.** Heartbeat test uses `temporalio.testing.ActivityEnvironment`
  with an `on_heartbeat` collector and a `functools.partial(heartbeat_during,
  interval_seconds=0.02)` monkeypatch, against a `sleep 0.3` test command —
  asserts ≥1 beat (would be 0 if the subprocess blocked the loop). Timeout test
  runs `sleep 5` with `test_timeout_seconds=1`. Backtracking test runs `(a+)+$`
  over 5000 'a's and asserts the call returns in <5s (rg is instant; Python `re`
  would hang).
