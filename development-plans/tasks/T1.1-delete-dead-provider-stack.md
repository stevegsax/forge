## Background and Detailed Explanation

Forge carried 1,400 lines of a provider layer that nothing imported — a
stale duplicate of the real one in sax-llm, yet still being edited and
still described in OVERVIEW.md as the live code. Worse, sax-llm's genuine
test suite physically lived in forge under names that disguised its
origin, which is why sax-llm's own coverage gate had been floored at
25%: its tests were being counted against the wrong project. This task
deleted the dead modules, moved the four test files home to sax-llm, and
raised that gate to the standard 85%.

The buried hazard was a one-line correctness fix hiding in the doomed
code. The dead client was the only place that constructed the Anthropic
client with `max_retries=0`. The live client used the SDK default of two
retries, and those stack *underneath* forge's own three-attempt retry
loop — up to nine provider attempts per failing call, with 429/529
back-off happening invisibly inside a single activity and hidden from
Temporal's timeouts. Deleting the dead copy without first porting that
line would have silently reintroduced the stacking. So the order was
load-bearing: port the retry fix into sax-llm, add a test that asserts
the SDK retries are disabled, *then* delete.

Two surprises surfaced on the way. sax-llm's `mistralai` pin had
resolved to a 2.3.1 wheel that installs with no importable package, so
the moved Mistral tests — the first to actually instantiate that
provider — failed until the dependency was constrained to `>=1.0.0,<2`
(the 2.x line is an incompatible SDK rewrite). And because T1.0's
sax-llm git-pin was still in place, forge's installed copy did not yet
see the retry fix — expected, and closed at the monorepo. Net effect:
deleting 1,400 lines of 0%-covered dead code lifted forge's own coverage
past its gate.

## Plan

Order matters: the `max_retries=0` fix lives only in the doomed
`forge/llm_client.py`, so port it into sax-llm **first**, then move tests, then
delete. Two commits — sax-llm first (retry fix + moved tests + cov gate), forge
second (deletions + docs + task bookkeeping).

Findings from reconnaissance:

- Forge's live code already consumes `sax_llm` everywhere (`get_provider`,
  `sax_llm.protocol`, `sax_llm.models`); nothing outside the dead package
  imports `forge.llm_client` / `forge.llm_providers`. So the deletion is safe.
- The four "sax-llm" test files in forge already import `sax_llm.*`; only
  `test_llm_client.py` carries a forge dependency (`forge.models` at lines
  363/378, plus reliance on forge's session-scoped `_register_output_types`
  conftest fixture for `TestGetOutputTypeRegistry` / `TestParseBatchResponseJson`).
- `tests/test_llm_providers_models.py` imports only `sax_llm.models` and is a
  redundant duplicate of sax-llm's existing `tests/test_models.py` → delete
  (not move).
- sax-llm already has thin `test_client.py` / `test_registry.py` / `test_models.py`;
  the moved files coexist (unique basenames, duplicate class names across
  modules are fine for pytest).
