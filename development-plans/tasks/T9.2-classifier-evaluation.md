# T9.2 — Classifier evaluation harness (phase-0 experiment)

**Status:** NOT STARTED

**Repos:** forge
**Depends on:** T9.1 (provenance ledger — dedup of the evaluation

**Last updated:** 2026-07-27

## Problem

The document-classifier design defers its riskiest parameters to
experiment rather than fiat: which model tier evaluates the AI
document-type fallback, whether prompt hints and few-shot examples pay
for themselves, and whether the deterministic-first premise (document
titles and filenames self-declare their type) holds on the real
corpus. Five measurements are required before classifier code is
written: (1) model-tier × prompt-variant document-type precision, per
type; (2) deterministic rule coverage — the fraction of documents
whose type is decided by title/structure/filename patterns without AI;
(3) the Company mention-vs-aboutness co-occurrence rate (an accepted
design risk that must be quantified); (4) the cross-SPV mention rate
(the gap report's false-present channel, also accepted risk);
(5) filename-rule precision (a name containing "subscription
agreement" usually is one — quantify "usually"). No ground truth
exists. The corpus is an admin-curated manifest of ~110k paths, an
estimated 10% unique after dedup.

## Background and Detailed Explanation

The product this feeds is an audit-completeness tool: auditors review
per-investment document sets against a standard expected-documents
checklist, and the gap report shows which expected documents are
present, missing, or pending review. That framing fixes the error
economics — a false "present" misleads an audit, while a miss merely
surfaces as "missing" and triggers a human look — so per-type
precision on checklist document types is the gating metric and recall
is advisory. The numeric ship bar is deliberately not set in advance:
the owner sets it after baseline numbers exist.

The experiment is cheap to run and expensive to label. The runtime
side rides infrastructure that already exists: the ocr app produces
text in dev, `sax_platform.llm` wraps the Anthropic Batch API (half
price, minutes-scale latency is fine) with structured outputs
validated against a schema, and model tiers are already configuration
(`ModelConfig`). The labels are the real work: the owner labels solo
for the foreseeable future. To make that tractable, labeling is
bootstrapped — title/filename rules and a model propose labels over
the deduped unique set, and the owner reviews proposals rather than
labeling cold. Bootstrapping doubles as a dry run of the review
workflow the product itself will ship.

Two hygiene rules protect the numbers. Rare document types will have
few examples — the bulk of the corpus is standard types — so the
report gives per-type precision and flags under-represented types as
unmeasured rather than pooling them into a flattering aggregate. And
because the corpus is full of near-duplicate variants of the same
underlying document, any document used as a few-shot exemplar in a
prompt is excluded from the scored set; scoring a model on a
near-copy of its own exemplar inflates precision.

The experiment sits outside every dependency that blocks the
classifier itself. The platform services the classifier needs
(documents store, WADM manager) do not exist yet; nothing in this
task needs them. The payoff is sequencing: by the time the classifier
is buildable, its riskiest parameters — model tier, prompt shape,
threshold posture, and the truth of two accepted-risk bets — have
numbers instead of guesses.

## Scope

- Standalone harness in forge (exact home decided at plan time):
  manifest in, measurement report out.
- Corpus: manifest lines consumed verbatim (no directory expansion);
  dedup through the provenance ledger (T9.1); sampling from canonical
  entries only.
- Text: the unique sample OCR'd through the existing ocr app in dev.
- Labels: stored with provenance — labeler, timestamp, cold versus
  bootstrapped — plus the bootstrap path (rules + model propose, owner
  reviews).
- Matrix: model tiers via `ModelConfig` × prompt variants (bare,
  +hints, +examples); calls through the platform batch wrapper;
  structured output constrained to the document-type label set plus a
  none-of-the-above escape; every result row stamped with model id and
  prompt-variant id.
- Report: the five measurements from the Problem statement; per-type
  precision mandatory.
- Out of scope: choosing the ship bar (owner decision after
  baselines); building any classifier component; near-duplicate
  detection beyond the ledger's byte identity.

## Acceptance Criteria

- [ ] Corpus selection consumes the manifest verbatim; no path outside
  the manifest is examined.
- [ ] Only canonical (deduped) documents enter the evaluation set;
  exemplar documents used in prompts are excluded from scoring.
- [ ] Every label row carries labeler, timestamp, and
  cold-versus-bootstrapped provenance.
- [ ] The report contains all five measurements; per-type precision is
  present for every document type with labeled instances, and
  under-represented types are flagged as unmeasured, never silently
  pooled.
- [ ] Every model result row is stamped with model id and
  prompt-variant id; re-running a matrix cell is idempotent.
- [ ] AI calls go through `sax_platform.llm` batch with structured
  output constrained to the label enum plus none-of-the-above.
- [ ] `make gates` green.
