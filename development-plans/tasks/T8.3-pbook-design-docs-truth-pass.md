## Background and Detailed Explanation

pbook's eight `pbook/design/` design docs were written 2026-06-09/10,
just before the merged plan's adjudications, so several of them still
record positions the merge later amended or scoped. This task is the
truth pass over all eight docs plus the pbook skill, run after
implementation — a companion to the earlier docs-only step that applied
the first amendments so the two design records would not contradict each
other mid-migration.

**What is actually wrong.** `TEMPORAL_PATTERNS` rule 8 is stated without
the scoping amendment the merge attached. `INTEGRATION.md` says nothing
about how forge consumes pbook, so it needs a forge-consumption section
documenting the view contract. The `DECISIONS.md` batch-threshold entry
lacks both the measured cost arithmetic (~110 sessions/month ≈
$2–5/month) and the explicit note that this batch-vs-sync reasoning does
*not* transfer to forge — a boundary that matters because forge's batch
decision is made on different grounds.

**The load-bearing factual bug.** The psycopg pooler wording is simply
wrong: the docs imply psycopg auto-disables prepared statements when it
talks to a transaction-mode connection pooler. It does not. Prepared
statements break on a transaction pooler (successive transactions can
land on different backend connections), so disabling them is the
application's job — `prepare_threshold=None` — not something the driver
does for you. A reader trusting the current wording would think they are
protected when they are not.

Finally, the pbook skill's `SKILL.md` gains its operational specifics —
worker requirements, degraded mode, the probation annotation, and the
pinned `uvx` invocation. Done when no design doc contradicts the
implemented system.

## Scope
