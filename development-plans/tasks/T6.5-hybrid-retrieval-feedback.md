# T6.5 — Hybrid retrieval + feedback

**Status:** NOT STARTED
**Phase:** 6 — Knowledge: pbook product + forge consumption
**Repos:** pbook
**Depends on:** [T6.3](T6.3-destructive-schema-migration.md)
**Last updated:** 2026-06-10

## Problem

pbook's retrieval is hierarchical and gated: zero-tag-overlap entries can
never surface, NULL-embedding entries are invisible, there is no lexical
search, and feedback is ignored on the query path. Retrieval must become
a union of lexical/semantic/tag candidate lists fused by one pure scoring
function — tags boost, never gate — with feedback events recorded and fed
back into ranking.

## Background and Detailed Explanation

T6.5 fixes pbook retrieval's recall holes: today entries that *should*
match a query can be structurally incapable of surfacing.

**The problem.** Retrieval is hierarchical and gated rather than
additive, and the gates hide entries. An entry with zero tag overlap
can *never* surface, no matter how well its text matches — the tag
filter runs first and excludes it. An entry with a NULL embedding is
invisible to the semantic path with nothing to fall back on, because
there is no lexical search at all. And feedback — whether a retrieved
entry actually helped — is recorded but ignored on the query path, so
the store never learns from use.

**The fix.** Retrieval becomes a *union* of three candidate lists —
lexical, semantic, and tag — fused by one pure scoring function,
`ranking.score_candidates`, with frozen weights. The key inversion is
"tags boost, never gate": tag overlap raises a candidate's score but
can no longer exclude one, so a strong lexical or semantic match
surfaces on its own merits. The fusion uses reciprocal-rank fusion
(RRF, k=60) over the lexical and semantic ranks, times a capped tag
boost, times mode alignment (CREATE vs FIX), times a feedback ratio
(gated to entries with ≥3 retrievals so the signal is not noise), times
a provisional 0.7 penalty for probation entries, then packs to the
token budget and records the retrieval event. A degraded mode covers a
missing `OPENAI_API_KEY`: lexical + tag only, flagged `"degraded":
"no_embedding_key"` so the caller knows semantic ranking was
unavailable rather than silently absent.

**Closing the loop.** `record_feedback` writes an event and bumps a
counter in the same transaction, so the feedback that ranking consumes
is exactly what was recorded — no drift. The CLI gains `invalidate`,
`review --stale`, and `purge` (the one remaining hard delete), and the
pbook skill is updated for the pinned uvx invocation, probation
annotations, and degraded mode.

**How you'll know it's done:** the two recall holes are closed by
explicit tests — a zero-tag-overlap entry surfaces via the
lexical/semantic lists, and a NULL-embedding entry surfaces lexically —
plus a per-session feedback idempotency test.

## Scope

- `ranking.score_candidates` (pure; frozen ScoringWeights): candidates =
  union of lexical/semantic/tag top-50 (status-filtered in SQL,
  `hnsw.iterative_scan` on); RRF k=60 over lexical+semantic ranks ×
  capped tag boost × mode alignment (CREATE/FIX) × feedback ratio (gated
  ≥3 retrievals) × probation ×0.7 (provisional); pack to token budget;
  record retrieval events.
- Degraded mode without `OPENAI_API_KEY`: lexical+tag,
  `"degraded": "no_embedding_key"`.
- Feedback: `record_feedback` event + same-transaction counter bump.
- CLI additions `invalidate`, `review --stale`, `purge` (the only hard
  delete).
- skill-pbook update (pinned uvx, probation annotation, degraded mode).
