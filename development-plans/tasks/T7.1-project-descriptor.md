## Problem

forge's context providers hardcode the literals `"forge"`, `"src"`, and
bare `python` in providers.py, so context discovery and exploration only
work against forge's own repository layout. PROVIDER_SPECS is a
hand-maintained menu that can drift from each provider's actual
parameter model. The merged plan carries Plan A's Phase 7 unchanged:
ProjectDescriptor is threaded through, hardcoded literals are deleted,
and PROVIDER_SPECS is derived so menu drift becomes impossible.

## Background and Detailed Explanation

Forge is meant to be task-agnostic — the project overview treats code
generation, research, and analysis as instances of one universal
workflow step, run against whatever repository a task targets. The
context engine is where that promise quietly breaks. The *context
providers* — the small pieces that fetch information for the LLM (read
a file, list a module's symbols, build the import graph) — have forge's
own layout baked in: the string `"forge"` as the package name, `"src"`
as the source root, bare `python` as the interpreter. Point forge at
any other repository and discovery looks in the wrong places.

**The fix.** Detect the project's shape once per task and carry it
everywhere it is needed. A frozen `ProjectDescriptor` records
`project_root`, `src_root`, `package_name`, `python_cmd`, `test_cmd`,
and `lint_cmd`, found by a pyproject-first heuristic chain and threaded
onto the context inputs (`AssembleContextInput`/`FulfillContextInput`).
Every hardcoded `"forge"`/`"src"`/bare-`python` literal in providers.py
is deleted in favor of reading those fields.

**The second half — menu drift.** During exploration the LLM is handed
`PROVIDER_SPECS`, a menu describing each provider and its parameters.
Today that menu is hand-maintained, so it can silently disagree with a
provider's actual parameter model — the LLM then asks for a field the
provider rejects, or never learns of one it accepts. T7.1 derives
`PROVIDER_SPECS` from each provider's `params_model`, so the menu and
the code cannot drift apart by construction.

**Why it leads Phase 7.** Every other Phase 7 task builds on the
descriptor: the worktree-accurate graph (T7.2) needs `src_root`, and
the token budget (T7.3) and exploration cap (T7.4) run per task through
the same context inputs. Done means the providers run green against a
non-forge repo in a test worktree (D96).

## Scope

- Frozen ProjectDescriptor (project_root, src_root, package_name,
  python_cmd, test_cmd, lint_cmd), detected once per task
  (pyproject-first heuristic chain), carried on
  AssembleContextInput/FulfillContextInput.
- Delete every hardcoded `"forge"`/`"src"`/bare-`python` literal in
  providers.py.
- **PROVIDER_SPECS derived from each provider's params_model** (menu
  drift impossible by construction).
