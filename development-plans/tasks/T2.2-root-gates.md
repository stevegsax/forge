# T2.2 — Root gates

**Status:** IN PROGRESS
**Phase:** 2 — Monorepo (forge, per D98)
**Repos:** forge monorepo (root, `.github/`, per-package pyprojects)
**Depends on:** [T2.1](T2.1-workspace-creation.md)
**Last updated:** 2026-07-16

## Problem

The five packages today have no CI and no import-linter anywhere, and
coverage gates are inconsistent (85/84/25/none/none). The merged topology
decision — one `libs/sax-platform` instead of two separate libs — explicitly
relies on import-linter to enforce layering *within* the single package:
`sax_platform.contracts` must stay sandbox-light and forbidden from
importing SDKs or shell siblings. The root gates are what make the one-lib
choice safe.

## Scope

Root justfile + GitHub Actions running ruff check/format, mypy,
`lint-imports`, pytest with per-package 85% coverage gates; import-linter
contracts: apps never import apps; libs never import apps;
**`sax_platform.contracts` may not import SDK/shell modules**
(forbidden-externals: boto3, sqlalchemy, anthropic, openai, mistralai +
internal shell siblings).

## Acceptance Criteria

- [ ] CI green on a no-op PR.
- [ ] A deliberate DAG-violating import fails `lint-imports`.

## Plan

*Written 2026-07-16. The task text predates D98 (it assumes a new `sax`
repo and the Phase-3 `sax_platform` package). This plan enforces the
D87 DAG on **today's** topology; the `sax_platform.contracts`
internal-layering contract lands in Phase 3 when that package exists.*

1. **Fix the four standing findings** (waiving pre-existing findings in
   the same change that turns on CI would be self-defeating): ruff
   `TC003` + `SIM117` in `tests/test_worker.py` (OVERVIEW's "2× TC003"
   was stale); mypy `type-arg`/`arg-type` in
   `src/forge/alembic/versions/002_idempotency_rekey.py`.
2. **Close the coverage-gate gaps** with real tests, then gate:
   - `libs/forge-contracts`: 30% → ≥85% (db, persist, temporal, types,
     constants, batch_jobs are at 0%), gate at 85.
   - `apps/ocr`: 67% → ≥85% (`cli.py` is 94 stmts at 0%; activities,
     store, worker gaps), gate at 85.
   - `apps/pbook`: 84.98% → ≥85% (one small genuine test), raise gate
     84 → 85. All five packages then gate at 85.
3. **import-linter** as a root dev dependency (grimp is already in the
   lock), config in root `pyproject.toml`, contracts:
   - apps never import apps: `pbook`/`ocr`/`forge` mutually forbidden,
     **except** forge → pbook, which is live until T6.4 deletes forge's
     ingestion side (flip to forbidden then).
   - libs never import apps, and libs stay independent of each other:
     `sax_llm` ↛ {forge, pbook, ocr, forge_contracts};
     `forge_contracts` ↛ {forge, pbook, ocr, sax_llm}.
   - `forge_contracts` may not import LLM SDKs (anthropic, openai,
     mistralai). boto3/sqlalchemy stay legal — they are real deps today
     (D89); the full sandbox-light forbidden-externals rule moves to
     `sax_platform.contracts` in Phase 3.
4. **Makefile gate targets** (`lint`, `typecheck`, `lint-imports`,
   `test`, `gates`), each package's suite run from its own directory
   per the workspace command discipline. *Deviation:* the task scope
   says "justfile"; the repo already has a Makefile as its command
   wrapper and one tool is enough — recorded in Development Notes.
5. **GitHub Actions** `.github/workflows/ci.yml`: jobs for
   lint+mypy+lint-imports, one test job per package (pbook against a
   pgvector service container via `PBOOK_TEST_DATABASE_URL`), plus a
   `postgres`-marker job (forge migration tests via testcontainers —
   currently never run automatically). uv-managed Python 3.14 from
   `.python-version`.
6. **Verify acceptance criteria**: a deliberate DAG-violating import
   fails `lint-imports` (add, observe failure, revert); push branch,
   open PR, CI green. mypy stays scoped to `src/forge` — widening it is
   T2.3a–d.
7. **Docs closeout**: OVERVIEW debt-table rows (CI, uneven gates, four
   findings), CHANGELOG row, TASKS.md checkbox, status → DONE.
