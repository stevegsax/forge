## Problem

- **Secrets bootstrap fails open.** `fetch-secrets.sh`'s `ssm()` helper
  swallows errors (`|| true`) and writes `KEY=` empty values for missing
  SSM parameters — workers boot, then fail at first use with no
  indication of which parameter was missing.
- **Temporal schema setup re-runs in production.** `compose.yaml` runs
  `temporalio/auto-setup:1.25.2` with `SKIP_SCHEMA_SETUP` commented out,
  so every container restart re-runs DDL against Supabase; auto-setup is
  documented not-for-production. Bootstrap also fetches docker-compose
  from GitHub `releases/latest` and uv via unpinned `curl | sh` —
  non-reproducible.
- **Terraform can replace the instance on a routine apply.** The
  latest-AL2023 AMI data source re-resolves; the AWS provider floor is a
  floating `>= 5.0`; state is local with no locking.
- **No S3 lifecycle rule.** Versioning is on with no expiry, so batch/OCR
  blobs and noncurrent versions accumulate forever — and the June review's
  §8 rejection of `schema_version` cites a "bucket TTL" that does not
  exist in the IaC.
- **Unquoted env sourcing.** `bootstrap-instance.sh` does
  `set -a; source /etc/forge/forge.env` with values written unquoted — a
  DB URL containing `&` executes the remainder as a shell command.
  systemd's `EnvironmentFile=` parses the same file safely; only the bash
  path is fragile.

## Scope

- `fetch-secrets.sh`: `require()` wrapper that aborts naming any missing
  required parameter (DB URL, ANTHROPIC_API_KEY, GitHub token, Temporal
  credentials, TLS material — non-empty checks on the TLS files); Mistral
  and OpenAI keys stay optional.
- Temporal: run schema setup as an explicit one-shot step; set
  `SKIP_SCHEMA_SETUP=true` in compose (or split to `temporalio/server` +
  a setup job). Pin docker-compose to an exact release and pin the uv
  installer version.
- Terraform: pin the AWS provider (`~> 5.x`); pin the AMI (variable
  default or `ignore_changes` on ami); add remote state with locking or
  record an explicit single-operator local-state waiver; note the
  EC2 egress-allowlist option the June sandbox rejection (macOS-reasoned)
  left open.
- S3: `aws_s3_bucket_lifecycle_configuration` — expire noncurrent
  versions, abort incomplete multipart uploads, object expiry consistent
  with the 25h batch-blob window. Correct the June review doc's §8
  schema_version rationale so it no longer cites a nonexistent TTL.
  Preferable before Phase 4 — T4.1's claim-check adds result blobs to
  this bucket.
- Bootstrap: replace the `source` with targeted extraction of the one
  value it needs, so the env file is never shell-evaluated.

## Acceptance Criteria

- [ ] A deliberately missing SSM parameter aborts boot with the parameter
      name in output; empty TLS files abort.
- [ ] Container restart performs no DDL against Supabase.
- [ ] `terraform plan` after an AMI release shows no instance
      replacement; provider pinned.
- [ ] Lifecycle rules present; review-doc rationale corrected.
- [ ] rg shows no shell `source` of the env file in deploy scripts.
