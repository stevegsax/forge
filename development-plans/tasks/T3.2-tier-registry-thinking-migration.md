## Problem

The forge and pbook model-tier maps are copies that have already drifted:
forge pins the stale legacy `claude-sonnet-4-5-20250929` while pbook's
worker default `claude-3-5-sonnet-20241022` is retired. The current Sonnet
is `claude-sonnet-4-6` (verified), on which `budget_tokens` is deprecated
in favor of adaptive thinking. One registry in the platform library ends
the drift; the thinking migration is a deliberate latency/cost behavior
change that must be made explicit.

## Scope

`sax_platform.llm.tiers` — CapabilityTier, ModelConfig, resolve_model, one
default map. Drift adjudicated: generation/summarization default
**`anthropic:claude-sonnet-4-6`** (forge's `claude-sonnet-4-5-20250929` is
stale legacy; pbook's worker default `claude-3-5-sonnet-20241022` is
retired). Migrate ThinkingConfig: `budget_tokens` is deprecated on 4.6 →
adaptive thinking; set `effort` explicitly (4.6 defaults to high — a
latency/cost behavior change). Delete forge/models.py:82-105 copy and all
forge imports; pbook's copy dies in T6.4.

### Amendments (2026-07-08)

- **Ordering constraint:** the thinking-shape migration must land before or
  with any pin bump. `budget_tokens` is rejected (400) on Opus 4.7+ and
  Sonnet 5, so pins cannot be modernized independently of the payload shape.
- **Re-verify the target model at execution time.** "Current Sonnet is
  `claude-sonnet-4-6` (verified)" was true on 2026-06-10 and is already a
  generation behind; the pin chosen here must be checked against the live
  API, not this file.
- **Delete the shadow fallbacks.** The registry consolidation must also
  remove the ~11 per-activity hardcoded model literals that bypass
  `resolve_model` whenever `model_name` arrives empty: `activities/llm.py:27`,
  `batch_submit.py:33`, `exploration.py:39`, `planner.py:202,324`,
  `sanity_check.py:169,245`, `conflict_resolution.py:230,312`,
  `eval/judge.py:26`, and the `cli.py:1617` help text.
- **Correct the false "adaptive" claims.** `cli.py:598` help and the
  `llm_client.py:87-91` docstring claim Opus runs adaptive thinking; no code
  path builds `{"type": "adaptive"}`, and `ThinkingConfig.effort`
  (`models.py:115-118`) is never serialized. Transmit effort for real or
  delete the field.
- **Fix the flag no-op, not just its help text (sweep, 2026-07-08).**
  `--thinking-budget` (default 10000) never reaches any LLM call in
  default single-step mode: the generation path drops thinking
  (`workflow_blocks.py:168` defaults it away; the sync-path
  AssembledContext has no thinking field), and no planner/sanity/conflict
  call exists at `plan=False`. The flag (or its post-migration effort
  successor) must either apply to the calls it claims to configure or the
  CLI must warn/error when it cannot apply.

### Design

1. **`sax_platform.llm.tiers`** (new module + tests): `CapabilityTier`
   (StrEnum), `ModelConfig` (pydantic, defaults = adjudicated pins,
   provider-qualified strings), `resolve_model(tier, config)`,
   `ThinkingPolicy` (frozen: `enabled: bool = True`, `effort:
   Effort = "high"`, `Effort = Literal["low","medium","high","xhigh",
   "max"]`) — the platform successor of forge's ThinkingConfig.
2. **sax_llm wire builders migrate** (forge still calls through them
   until T3.5/T3.6): `build_thinking_param(model, ...)` builds
   `{"type": "adaptive"}` / `{"type": "disabled"}` for adaptive-gen
   Anthropic models (haiku/non-Anthropic → None, unchanged);
   `budget_tokens` deleted from its signature and from
   `build_messages_params`/batch body building, which instead accept
   the policy and transmit `output_config: {"effort": ...}` when
   thinking is enabled. D62's mechanism dies (D94 already records the
   supersession).
3. **forge sweep**: delete `models.py` tier map + `resolve_model` +
   `ThinkingConfig` (imports move to `sax_platform.llm.tiers`; forge
   gains its first dependency on sax-platform — wired in root
   pyproject); replace all 11 shadow-fallback literals with registry
   resolution at each site's tier (mapping recorded below); CLI:
   `--thinking-budget` replaced by `--effort` (choices low..max,
   xhigh included) + existing `--no-thinking`; per the sweep
   amendment, when `plan=False` and the user explicitly passes
   `--effort`/`--no-thinking`, the CLI **warns** that single-step mode
   has no thinking-configurable calls (the generation path explicitly
   disables thinking — unchanged behavior, now visible); `cli.py:598`
   and `:1514` help text corrected to describe what the code does.
4. **DECISIONS**: dated note on D94 recording the re-verified pins
   (sonnet-5/opus-4-8, budget-style 400 proven; D10/D58 amendment
   notes already point at D94 and stay).

Shadow-fallback tier mapping: activities/llm.py, batch_submit.py,
exploration.py → GENERATION; planner.py (2), conflict_resolution.py
(2), sanity_check.py (2) → REASONING; eval/judge.py → REASONING
