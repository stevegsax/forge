# T6.4 — IngestWorkflow + CurationWorkflow

**Status:** NOT STARTED
**Phase:** 6 — Knowledge: pbook product + forge consumption
**Repos:** pbook, forge (forge's ingestion side deleted in the same
change)
**Depends on:** [T6.3](T6.3-destructive-schema-migration.md)
**Last updated:** 2026-07-08

## Problem

Ingestion inverts to pbook end-to-end: today forge drives pbook's
extraction cross-queue over a raw-JSON contract, session rows are seeded
by the CLI rather than owned by the workflow, one bad experience kills the
whole batch, and pbook's worker registers a retired model through its own
drifted tier-registry copy. The replacement is two real workflows —
durable ingest and weekly curation — with `pbook ingest` as the only
frontend and forge's entire ingestion side deleted in the same change.

## Background and Detailed Explanation

T6.4 is where Phase 6's central inversion actually happens: ingestion
stops being something forge does *to* pbook and becomes something pbook
owns end to end. This task implements reversal R2 (D91).

**The problem.** Today ingestion is split awkwardly across both apps.
forge drives pbook's extraction cross-queue over a hand-rolled raw-JSON
contract; the session row is seeded by the CLI instead of being owned
by the workflow that populates it; a single bad experience in a
transcript aborts the whole batch; and pbook's worker registers a
*retired* model because it still carries its own drifted copy of the
tier registry. Extraction also runs through the batch path, adding
up-to-24-hour round-trips to a freshness-sensitive loop for a volume
(~110 sessions/month) that batching would save only a few dollars a
month.

**The fix.** Two real durable workflows replace the split.
`IngestWorkflow` (id `pbook-ingest-{session_id}`) owns the whole flow:
its first activity writes the `running` session row (the CLI never
seeds), it claim-checks transcripts by path, runs one synchronous
structured-output analyze activity with a heartbeat, and processes each
experience under its own try/except so one failure can no longer kill
the batch. Each survivor is extracted (GENERATION tier, cached static
system prompt), judged (CLASSIFICATION tier), embedded, and saved with
`ON CONFLICT (origin_hash) DO NOTHING` — deterministic idempotency, so
a retry cannot duplicate. `CurationWorkflow` runs weekly on a Schedule:
a staleness sweep, per-cluster consolidation behind the same judge
gate, and an abandoned-session sweep (a session stuck `running` >48h
becomes `error`). The LLM calls are synchronous, not batched — that is
R2 (D91): the volume does not justify batch latency, and the boundary
is explicitly scoped to pbook so it never erodes forge's batch-first
default.

**What gets deleted — stop looking for it afterward.** forge's
*entire* ingestion side goes in this same change: the ingestion
workflow and activities modules (`ingestion_workflow.py`,
`activities/ingestion.py`), the pbook imports and
`_INGESTION_AVAILABLE` guards, the direct DB read in `cli.py`, and the
`forge ingest` command. After T6.4, `pbook ingest` is the only
ingestion frontend, the cross-queue worker count drops to zero
cross-calls, and the two-worker cross-queue ingestion tests go with it.
pbook's duplicated tier-registry copy is also deleted here (it uses
`sax_platform.llm.tiers` instead) — this is the task the repo's
standing "pbook keeps its own tier map until T6.4" note has been
pointing at.

**The restored gem (2026-07-08 capture sweep).** Tag inference is
finally enforced at write. The June review assigned pbook a single
namespaced tag inferrer enforced at write time, but it was dropped when
this file was first written — `insert_entry` never calls the
`validate_tags`/`parse_tag` functions that already exist in
`pbook/tags.py`, so taxonomy-violating tags enter the store durably and
quietly degrade both T6.5's tag-boost ranking and T6.7's forge
tag-overlap consumption. T6.4 validates and normalizes tags in the
embed+save activity, and it is never save-failing: an invalid tag is
dropped or normalized with a logged reason, never a rejected entry.

## Scope

`IngestWorkflow`:

- Id `pbook-ingest-{session_id}`; union input
  TranscriptSource|InlineExperiences.
- First activity writes the `running` session row — CLI never seeds.
- Claim-check transcripts by path.
- One sync structured-output analyze activity with heartbeat.
- Per-experience try/except isolation.
- Extract GENERATION/sonnet with cached static system prompt → judge
  CLASSIFICATION/haiku → embed+save `ON CONFLICT (origin_hash) DO
  NOTHING`; survivors → probation, judge failures →
  rejected_by='validator'; workflow error handler records `error`.

`CurationWorkflow` (weekly Schedule `pbook-curation-weekly`, idempotent
creation):

- Staleness sweep (pure `compute_staleness`, provisional constants
  270/540d documented as provisional).
- Consolidation per-cluster isolated (same judge gate; one-transaction
  apply: survivor → probation with zeroed counters, parents → superseded,
  sources reparented).
- Abandoned-session sweep (>48h running → error).

Surrounding changes:

- pbook composition root from T3.6; delete pbook's tier-registry copy
  (use `sax_platform.llm.tiers`).
- **Restored disposition (2026-07-08, capture sweep):** one namespaced tag
  inferrer, enforced at write. The June review's knowledge-architecture
  disposition assigned this here ("T6.4 — single namespaced inferrer
  enforced at write"; convergence point 9: "namespaced tags normalized at
  write, never save-failing"), but it was dropped when this file was
  written — the extraction gap was caught by the 2026-07-08 sweep.
  pbook's `insert_entry` (`pbook/store.py:438-461`) never calls the
  `validate_tags`/`parse_tag` functions that exist in `pbook/tags.py`, so
  taxonomy-violating tags enter durably and degrade both T6.5's tag-boost
  ranking and T6.7's forge tag-overlap consumption. Tags are
  validated/normalized in the embed+save activity — never save-failing
  (invalid tags dropped/normalized with a logged reason, not a rejected
  entry).
- **Delete forge's ingestion side in the same change**
  (ingestion_workflow.py, activities/ingestion.py, pbook imports,
  `_INGESTION_AVAILABLE` guards, cli.py:1217 direct DB read,
  `forge ingest`); `pbook ingest` is the only frontend.
- Replay tests; cross-queue worker count drops to zero cross-calls.
