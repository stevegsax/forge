## Problem

Three observability defaults misbehave:

1. **Prompt-leak channel via the root logger.** `cli.py:489-490` sets the
   *root* logger to DEBUG whenever the file handler attaches, so every
   third-party library's DEBUG stream lands in `forge.log`/`worker.log` —
   and any SDK that logs payloads at DEBUG leaks prompts into log files,
   outside the trust boundary the 2026-06 review analyzed when it refuted
   the store-retention finding (the refutation covered the interactions
   table, not logs).
2. **Dead config knob.** `FORGE_OTEL_ENDPOINT` (`tracing.py:33`) is
   defined but never read — `init_tracing`'s `endpoint` parameter is only
   honored when passed explicitly, and the sole production caller is bare
   `init_tracing()` (`worker.py:224`). Configuring it silently does
   nothing.
3. **Span spam by default.** `resolve_exporter_type` defaults to CONSOLE
   with a synchronous `SimpleSpanProcessor` (`tracing.py:98`, `:167-170`),
   printing every span to stdout on local runs — contradicting D85's
   quiet-worker design. The EC2 units mask it with
   `FORGE_OTEL_EXPORTER=none`; local dev gets the spam.

## Scope

- Root logger at INFO; `forge.*` loggers at DEBUG.
- Wire `FORGE_OTEL_ENDPOINT` into `init_tracing` or delete the constant.
- Default exporter `none`; console/OTLP opt-in.

Coordinate note: T3.6 reworks tracing *composition* (set-once guard,
composition roots). This task changes *defaults* only — disjoint, but
whichever lands second should re-verify the other's behavior.

## Acceptance Criteria

- [ ] File logs contain no third-party DEBUG records (test with a noisy
      third-party logger).
- [ ] A bare `forge worker` run emits no per-span stdout.
- [ ] `FORGE_OTEL_ENDPOINT` is honored (test) or gone (rg).
