# T3.6 — Composition roots everywhere

**Status:** DONE
**Phase:** 3 — `sax_platform` consolidation + structured outputs
**Repos:** sax monorepo (all packages)
**Depends on:** [T3.4](T3.4-platform-plumbing-modules.md)
**Last updated:** 2026-07-08

## Problem

There is no composition root anywhere: a module-global Temporal client,
per-call engines, sax-llm global caches and a registry forked three ways,
zero Settings classes, and 14+ point-of-use env reads — and tests
monkeypatch globals to cope. Both review plans independently converged on
killing all module-level singletons: frozen per-process Settings (env read
only there, fail-fast) and class-based activities with bound methods —
Temporal's sanctioned dependency injection.

*(2026-07-08 sweep note)* "One engine per process" is load-bearing, not
hygiene: each per-call Postgres engine carries `pool_size=5 +
max_overflow=5` (forge-contracts `db.py:74`) and holds its connections
until garbage-collected, so concurrent activities across two worker
instances can exhaust Supabase's connection cap.

## Scope

Frozen `ForgeSettings`/`OcrSettings`/`PbookSettings` constructed once in
worker/CLI mains, fail-fast; class-based activities — forge
`StoreActivities(engine)`, `LlmActivities(llm, output_types)`,
`BatchActivities(llm, output_types, engine, blob_store)`,
`ContextActivities(engine)`; ocr/pbook mirrored; one engine per process;
delete `batch_poll.set_temporal_client`, every per-call
`get_store_engine()`, sax-llm `_provider_cache`/`_client` + all
`reset_*()`, pbook `set_provider`/`_engines`/`_client`, the
`dispose_store_engines` global-sqlalchemy monkeypatch fixtures; pbook's
runtime `os.environ` write → `cfg.attributes`; tracing cleanup (delete the
`_TRACER_PROVIDER_SET_ONCE` private-API reset; fix the three false "pure"
docstrings); `sax_platform.testing` (temporal_env fixture + provider
fakes) imported explicitly by app conftests — **no pytest11 plugin**.

## Plan

Plan written 2026-07-18 after a three-agent exploration sweep (forge wiring +
full activity inventory; ocr/pbook wiring + platform config state; test
infrastructure + blast radius). Execution: **Opus subagents** in waves, same
orchestration as T3.4/T3.5. Implementation starts on operator go-ahead.

### State findings that shape the design

- **The codebase is already T3.6-shaped at the core**: every activity module
  has `execute_*(input, dep)` with directly-injected deps and thin shells
  acquiring module-global seams. T3.6 is chiefly: build composition roots,
  convert shells to bound methods, delete 9 seams. The seam clear-list
  (verified sweep): forge `llm_client._llm`, `batch_submit._batch_client`,
  `batch_poll._temporal_client` + `._batch_client`,
  `_mistral._mistral_ocr`; ocr `deps._mistral_ocr`; pbook `llm._provider`,
  `embeddings._client`, `store._engines`. **sax_platform is already at
  zero.**
- **"One engine per process" fixes a live defect**: the platform
  `get_store_engine()` has NO cache — forge's ~11 store call sites and ALL
  12 ocr activities build a fresh Postgres pool (`pool_size=5 +
  max_overflow=5`) per invocation (the sweep note's Supabase-cap risk is
  real).
- **Class conversion is invisible to workflows**: all 35 forge activities
  use bare `@activity.defn` (registered name = `__name__`) and workflows
  invoke by string name; bound methods keep `__name__`. The 12 by-name
  workflow-mock test files are unaffected.
- **pbook's worker never adopted the T3.4 scaffold** (raw `Client.connect`,
  no TLS chokepoint, own drain loop) — modernized here while its main is
  restructured anyway.
- **Scope exclusion**: D93's deletion list includes "the workflow-test
  harness's 30 globals and 11 resets" — those are **T5.5's**
  (`ScenarioState` closures per CLAUDE.md); T3.6 does not touch
  `tests/test_workflows.py` scenario state. Also out of scope: the ~11
  hardcoded model fallbacks (review §3.4 — tier hygiene, not composition).

### Design

**Settings.** Per-app composites live app-side; the T3.4 platform groups are
the building blocks. `ForgeSettings` (`src/forge/settings.py`):
`temporal/db/blob/llm/log` groups + a forge-local `TracingSettings`
(`FORGE_OTEL_EXPORTER`; the never-read `FORGE_OTEL_ENDPOINT` const dies) —
built ONCE, fail-fast, at worker main. `OcrSettings` (temporal/db/blob +
mistral key). `PbookSettings` (pbook-local groups: `PBOOK_DATABASE_URL`
optional → store-disabled semantics preserved, `PBOOK_DB_POOLER`,
`PBOOK_LOG_PATH`, `OPENAI_API_KEY`). **CLI commands construct exactly the
groups they need at command start** (a full composite would make `forge run`
demand `FORGE_DB_URL` it never uses — fail-fast applies to what a command
actually needs; click `envvar=` option declarations remain as CLI-argument
surface). Settings groups become the only keyed env readers; the two
`allowlist_env(os.environ)` subprocess passthroughs are legitimate and stay.

**Platform signature conversions** (`sax_platform`): `build_tls_config` /
`connect_temporal` gain a `TemporalSettings` parameter;
`get_store_engine(url, *, pooler_override=False)` explicit (env-reading
no-arg form + `get_store_url()` deleted at the end); `contracts.s3_blobs`
module fns → an **`S3Blobs(bucket, prefix)` class** (boto3 stays lazy;
sandbox-light preserved) and `resolve_batch_result(result, blobs)` takes it;
`make_mistral_client(api_key)` loses its env fallback (roots pass
`LlmSettings.mistral_api_key`). Transition: new signatures land FIRST with
temporary env-fallback defaults so suites stay green per wave; fallbacks are
deleted in the final wave.

**Forge activity classes** (only dependency-carrying activities become
methods; no-dep activities — git ×4, validate, write ×2, the four pure
`assemble_*_context` prompt builders, `detect_file_conflicts`,
`evaluate_transition` (D95 deletes later), `prepare_transcript` — stay free
functions):

- `StoreActivities(engine)` — fetch_extraction_input,
  save_extraction_results, persist_to_store, fetch_existing_playbooks,
  fetch_playbook_ids, export_single_playbook.
- `ContextActivities(engine)` — assemble_context, assemble_step_context,
  assemble_sub_task_context, fulfill_context_requests (engine threads into
  `providers.py`'s `handle_past_runs`/`handle_playbooks`, replacing their
  per-call engines).
- `LlmActivities(llm)` — call_llm, call_planner, call_exploration_llm,
  call_sanity_check, call_conflict_resolution, call_extraction_llm,
  review_manual_playbook. *(Deviation: the task's `(llm, output_types)`
  sketch predates T3.5 — sync sites import their pydantic types directly;
  no lookup exists to inject.)*
- `BatchActivities(client, output_types, engine, blob_store,
  temporal_client, mistral_ocr)` — submit_batch_request, submit_batch_blob,
  poll_batch_results, parse_llm_response. Replaces both `_batch_client`
  caches, `set_temporal_client`, `_mistral`'s cache (root builds
  `MistralOcr` iff the key is set; `mistral_ocr: MistralOcr | None` with
  the current clear-error semantics), and completes batch_poll's partial
  injection (`_poll_batch_for` deps become constructor state).

Worker main: `ForgeSettings()` → migrations → tracing → connect (settings)
→ build engine/llm/client/blobs/mistral/temporal-client ONCE → construct
the four classes → register bound methods + free functions (same names) →
platform `run_worker` → `finally: shutdown_tracing()`. CLI: `eval-planner`
threads an `AnthropicLLM` into `judge_plan` (llm param);
`forge/llm_client.py` deleted; forge's `ingest` command uses pbook's new
composition helper (below).

**ocr**: `OcrStoreActivities(engine, blobs)` with the 12 methods (engine
built once — ends the per-call pool churn); `deps.py` deleted (no production
consumer; Phase 4 composes directly); worker builds `MistralOcr` at startup
via settings; **ocr adopts `sax_platform.logging.setup_logging` +
`silence_noisy_loggers` — its first logging ever**.

**pbook**: `PbookStoreActivities(engine | None)` (store-disabled semantics
preserved), `PbookLlmActivities(provider)` for llm_chat,
`EmbeddingActivities(embedder | None)` for llm_embed; `set_provider`/
`_provider`, `embeddings._client`, `store._engines` deleted; worker moves
onto `connect_temporal` + the platform `run_worker` scaffold; a public
composition helper **`pbook.store.build_engine(settings) -> Engine | None`**
(the contract forge's CLI codes against — replaces forge's direct
`pbook.store.get_store_engine()` calls); migrations pass the URL via alembic
**`cfg.attributes`** (env.py reads attributes → sqlalchemy.url →
`PBOOK_DATABASE_URL` env fallback kept only for the operator's standalone
alembic CLI; the runtime `os.environ` WRITE dies); logging via platform
`setup_logging` (keeps `PBOOK_LOG_PATH` semantics through `log_path=`;
rotation moves to the unified 10 MB × 5 — behavior change, noted).

**Tracing cleanup** (scope item): delete the `_TRACER_PROVIDER_SET_ONCE`
private-API reset in `init_tracing` (no test depends on re-init); fix the
three false "pure" docstrings by making `resolve_exporter_type(value)` pure
(exporter arrives from `TracingSettings`); delete the dead
`FORGE_OTEL_ENDPOINT_ENV` constant.

**`sax_platform.testing`** (new module, test-only by design — imports
pytest at module scope; pytest stays a dev-group dep; no pytest11 entry
point): `temporal_env` (session-scoped, `loop_scope="session"`, WITH
`pydantic_data_converter` — the forge/ocr shape), `FakeLLM` (recording,
canned `Completion`s or typed-outcome raises — replaces forge's
`build_mock_llm` and pbook's `_StubProvider`), `FakeMistralOcr` (async
submit/poll/process — replaces bare MagicMocks). App conftests import
explicitly. **Flag**: pbook's 4 per-file env fixtures currently lack the
pydantic converter (a test/prod mismatch — its worker connects WITH it);
unification fixes it but those files may need serialization touch-ups.

**Test rewrites** (bounded; workflow-mock files untouched): 13 `get_llm`
patch sites / 7 files → construct `LlmActivities(FakeLLM)`; 2
`_get_batch_client` + 3 temporal-client patches → `BatchActivities(...)`
construction; pbook's 13 `set_provider` sites + 3 reset fixtures →
`PbookLlmActivities(fake)`; forge test_cli's 11 `pbook.store.
get_store_engine` patches → patch `pbook.store.build_engine`; delete both
`dispose_store_engines` fixtures (tests own engine lifecycle via explicit
fixtures) and the `_reset_mistral_ocr_cache` autouse fixture.

## Development Notes

- 2026-07-18 — Plan written (three-agent exploration sweep; implementation
  awaits operator go-ahead). Key pre-coding decisions:
  1. **Deviation from the Scope sketch:** `LlmActivities(llm)` drops the
     `output_types` param — T3.5's frozen-mapping migration left sync sites
     importing their pydantic types directly; only `BatchActivities` has a
     lookup to inject. No-dep activities (git/validate/output/pure
     assembles/evaluate_transition/prepare_transcript) stay free functions —
     classes exist to carry dependencies.
  2. **Scope boundaries made explicit:** D93's "workflow-test harness's 30
     globals and 11 resets" belong to T5.5 (ScenarioState), not here; the
     review's ~11 hardcoded model fallbacks (§3.4) are tier hygiene, not
     composition — untouched.
  3. **CLI settings semantics:** per-command group construction (not one
     composite) so `forge run` doesn't fail-fast on a DB URL it never uses;
     the worker gets the full `ForgeSettings` composite. click `envvar=`
     declarations remain (CLI-argument surface, not point-of-use config).
  4. **Cross-package contract:** forge's CLI stops reaching into
     `pbook.store.get_store_engine()`; pbook exposes
     `build_engine(settings) -> Engine | None` and forge codes against it.
  5. **Found live defect** the task's sweep note predicted: the platform
     engine factory has no cache, so ocr builds a fresh pool per activity
     call (×12 activities) — "one engine per process" is load-bearing.
  6. **Transition strategy:** platform signature changes land first with
     temporary env fallbacks (suites green per wave); fallbacks deleted in
     the final wave with the AC sweeps.
