## Background and Detailed Explanation

This is a truth-in-labeling pass over forge's tests and its
status-of-record doc. The test problem is a name that lies twice.
`tests/test_e2e.py` is not an end-to-end suite at all — it runs by
default with the LLM calls mocked, i.e. it is a plain integration suite.
Meanwhile the `e2e` marker is defined but collects nothing in forge (the
env-gated real-API tests actually live in ocr), yet `CLAUDE.md` still
tells readers to run `uv run pytest -m e2e` — a command that runs zero
tests. Anyone trusting that line as their real-API smoke test gets a
green result from having run nothing.

**The fix.** Rename `tests/test_e2e.py` → `tests/test_pipeline.py` to
match what it is (a default-run, mocked-LLM integration suite), delete
the stale `-m e2e` line from `CLAUDE.md`, and document the marker scheme
plainly: `e2e` means env-gated real-API tests and lives in ocr;
`postgres` is opt-in and mandatory for the pgvector/knowledge paths.
Done when the markers match reality — `pytest -m e2e` collects only
env-gated tests.

**The docs half.** `docs/OVERVIEW.md` is the status-of-record but
predates the migration: it still describes deleted subsystems and lists
technical debt the migration closed. Rewrite its status, module map, and
tech-debt table — items 1/2/3/5 closed with their dispositions, and the
transition-vocabulary row moved to deferred-by-decision — so the
status-of-record actually records the current status.
