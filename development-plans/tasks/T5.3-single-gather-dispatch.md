# T5.3 — Single gather + dispatch

**Status:** NOT STARTED
**Phase:** 5 — Workflow consolidation (forge)
**Repos:** forge
**Depends on:** [T5.2](T5.2-single-step-block.md)
**Last updated:** 2026-07-08

## Problem

The fan-out gather code exists twice in `workflows.py` (parent and
nested), and the duplicated nested copy is where the T1.5 propagation bug
(`resolve_conflicts`/`thinking`/`model_routing` dropped) was bred. The
four batch LLM-dispatch arms (planner, sanity, exploration, conflict) each
carry their own copy of the call/submit/parse plumbing rather than sharing
one implementation on the Phase-4 transport.

## Background and Detailed Explanation

T5.3 is the fan-out counterpart to T5.2: it collapses two copies of
the gather logic into one and unifies four copies of the batch-call
plumbing, then uses the single surviving gather to fix a failure mode
where one crashed child destroys the whole run and kills its siblings
mid-batch.

**The problem.** Two duplications live here. First, the fan-out
*gather* — start N child workflows, wait for them, merge their outputs
— is written twice in `workflows.py`, once for the top-level fan-out
and once for a fan-out nested inside a sub-task. The nested copy is
where the T1.5 propagation bug was bred: `resolve_conflicts`,
`thinking`, and `model_routing` were honored by the parent path and
silently dropped by the nested one. Second, the four batch
LLM-dispatch arms — planner, sanity check, exploration, conflict
resolution — each carry their own copy of the submit/poll/parse
plumbing instead of sharing the one transport Phase 4 built.

**The fix.** `blocks/gather.py` exposes a single
`run_fan_out_gather(..., commit)` used by both callers — the parent
passes `commit=True`, the nested passes `commit=False` (per D16,
nested results merge upward without their own commit) — so the T1.5
fix lives in exactly one place and cannot drift again.
`blocks/dispatch.py` exposes `typed_batch_dispatch`, one
implementation of call → submit → parse on the Phase-4 timer-loop
transport, shared by all four arms.

**The buried gems (the 2026-07-08 amendments).** Two defects the
consolidated gather is the right place to fix once. *Per-child failure
isolation:* today both gathers bare-await their children, so a child
that *raises* — an execution timeout, a batch error, a 25h wait expiry
— propagates a `ChildWorkflowError` straight out of `run()`. The
consequences cascade: no `TaskResult`, no run record, no worktree
cleanup, and — because the default ParentClosePolicy is TERMINATE —
every in-flight sibling is killed, orphaning the paid batches they
were waiting on. The correct pattern (wrap each child await in
try/except so a failure becomes a failed `SubTaskResult` while
siblings run to completion) already exists in this codebase at
`ingestion_workflow.py`; T5.3 brings it to the forge gather and makes
the chosen ParentClosePolicy explicit rather than defaulted. *Uniform
interaction records:* exploration is the one dispatch path of the five
that writes nothing to the interactions store — up to 20 LLM calls per
task with no token or cost record — which also leaves T7.4's future
budget enforcement with nothing to enforce against. The consolidated
dispatch persists an interaction record, with token counts, for every
arm.

**How you'll know it's done:** the depth-2 nested-fan-out regression
stays green; the four arms share one implementation; a raising child
yields a failed `SubTaskResult` while its siblings finish and the
parent still returns a `TaskResult` and writes a run record; and every
dispatch arm produces an interaction record with token counts.

## Scope

- `blocks/gather.py` — `run_fan_out_gather(children, fan_out, settings, *,
  commit)` for parent (commit=True) and nested (commit=False, D16) — the
  T1.5 fix now lives in exactly one place.
- `blocks/dispatch.py` — `typed_batch_dispatch` consolidating the
  planner/sanity/exploration/conflict arms onto the Phase-4 transport.

### Amendments (2026-07-08)

- `run_fan_out_gather` must isolate per-child failure: wrap each child
  await in try/except so a *raising* child (execution timeout, batch error,
  wait expiry) yields a failed SubTaskResult instead of a
  `ChildWorkflowError` escaping `run()`. Today the gathers bare-await
  (`workflows.py:1230-1233`, `:1720-1724`): no TaskResult, no run record,
  no worktree cleanup, and the implicit default ParentClosePolicy
  (TERMINATE) kills in-flight siblings, orphaning their paid batches. The
  correct pattern already exists in `ingestion_workflow.py:264-299`.
- Choose and document an explicit ParentClosePolicy for fan-out children.
- *(2026-07-08 sweep)* `typed_batch_dispatch` persists an interaction
  record for every arm uniformly — exploration is currently the only one
  of the five dispatch paths that writes nothing to the interactions
  store (`workflows.py:380-400`; up to 20 calls/task with no token/cost
  record), which also makes T7.4's budget enforcement unverifiable.
