# T6.7 — Forge consumption + playbooks deletion

**Status:** NOT STARTED
**Phase:** 6 — Knowledge: pbook product + forge consumption
**Repos:** sax-platform (contracts), forge, pbook (schema-sync test)
**Depends on:** [T6.3](T6.3-destructive-schema-migration.md) (the
`knowledge.approved_entries` view); Phase 5
([T5.5](T5.5-harness-rebuild-replay-tests.md)) for the forge side
**Last updated:** 2026-06-10

## Problem

The knowledge loop is disconnected — pbook knowledge never reaches forge
task execution (a confirmed critical finding). The read-only
`knowledge.approved_entries` SQL view is the only consumption path that is
deterministic, dependency-light, and DAG-clean; the view exposes
`search_tsv` so retrieval follows the "tags boost, never gate" rule
instead of tag-gated candidates that can never surface zero-tag entries.
Separately, forge's own playbooks subsystem is superseded by pbook (owner
decision) and must be deleted — table, extraction/manual/export
workflows, CLI, and tag inferrers.

## Background and Detailed Explanation

T6.7 closes Phase 6's loop: forge finally *reads* pbook's knowledge,
and forge's own parallel knowledge store is deleted. This is the task
that turns forge into pbook's consumer.

**The problem.** The knowledge loop was disconnected — a confirmed
critical finding. pbook accumulates validated knowledge, but none of it
ever reached forge task execution, while forge maintained its *own*
playbooks store in parallel — a second knowledge base, polluted by the
re-extraction loop's duplicates, feeding the orchestrator poorly. Two
stores, neither doing the job.

**The fix — consumption.** pbook publishes a read-only SQL view,
`knowledge.approved_entries` (built in T6.3), and forge reads it.
`sax_platform.contracts.knowledge` holds the read-only table
definition, a frozen `KnowledgeEntry` model, and a query helper.
forge's `assemble_context` and its exploration playbook provider switch
to that view: one deterministic SQL read — lexical rank
(`websearch_to_tsquery` + `ts_rank_cd`) UNION tag-overlap candidates —
fused by a small pure scorer with a capped tag boost (tags boost, never
gate), sliced to the token budget, active entries only. The view is
chosen deliberately as the only consumption path that is deterministic,
dependency-light, and DAG-clean — a library or CLI path would recreate
app-to-app coupling or put a uvx invocation on the context-assembly hot
path. A load-bearing constraint: **no embeddings and no OpenAI on
forge's hot path** — forge takes the cheap deterministic slice, and
pbook's full hybrid retrieval stays pbook's own surface. A pbook-side
schema-sync test after every migration keeps the view contract honest.

**The fix — deletion. Stop looking for forge playbooks after this.**
forge's playbooks subsystem is superseded by pbook (owner decision) and
is deleted entirely: the `playbooks` table, its extraction, manual, and
export workflows, the `playbook_review`/`export` activities, the `forge
playbooks` CLI, and forge's tag inferrers all go away, and OUTPUT_TYPES
becomes a true module constant with the last string-keyed entry gone.
Existing rows are *not* blanket-migrated — the table is polluted by
re-extraction duplicates that do not meet pbook's judged-entry bar — so
they get a one-time JSON dump and manual triage via `pbook add`. This
supersedes D13 and D43–D47.

**How you'll know it's done:** forge context assembly shows pbook
entries in a live test against podman Postgres, a degraded-mode test
covers the knowledge DB URL being unset (empty result plus a log line,
never a crash), and the forge suite is green with the whole playbooks
subsystem gone.

## Scope

- `sax_platform.contracts.knowledge` — read-only `sa.Table` for
  `knowledge.approved_entries` + frozen `KnowledgeEntry` + query helper
  (lexical `websearch_to_tsquery`/`ts_rank_cd` UNION tag candidates).
- forge `assemble_context` + the exploration playbook provider switch to
  it: deterministic SQL read + small pure fused scorer (capped tag boost
  — tags never gate) + token-budget slice, active-only; **no
  embeddings/OpenAI on forge's hot path**.
- Explicit degraded-mode test (knowledge_db_url unset → empty + log).
- pbook-side schema-sync test asserting the view shape after every pbook
  migration.
- **Forge playbooks deletion**: one-time JSON dump → manual triage via
  `pbook add` (**no blanket-approve migration** — the table is polluted
  by re-extraction duplicates); drop table + store helpers + Alembic
  migration; delete manual/export playbook workflows,
  playbook_review/export activities, `forge playbooks` CLI, forge tag
  inferrers; OUTPUT_TYPES becomes a true module constant.
- DECISIONS supersessions D13/D43–D47.
