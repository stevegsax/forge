## Problem

Fuzzy-matched edits are applied silently: nothing in validation/domain
config governs whether fuzzy application is allowed or at what
threshold, and an applied fuzzy edit leaves no trace in
ValidationResult or the run records — so a branch reviewer cannot see
that an edit landed by approximate match. The merged plan's verified
safety kernel keeps fuzzy-edit surfacing (the `allow_fuzzy` knob,
applications visible in ValidationResult) while rejecting the heavier
governance machinery.

## Scope

- `allow_fuzzy`/`fuzzy_threshold` on validation/domain config.
- write_output surfaces fuzzy-applied edits (path, score) into
  ValidationResult/run records so branch reviewers see them.
- D55–D57 reaffirmed.
- (The ast.parse gate stays rejected — a valid wrong-location edit
  passes it by definition.)

### Amendments (2026-07-08, capture sweep)

- **Fix the metric before tuning the threshold.** `SequenceMatcher` runs
  with default `autojunk=True` (`output.py:286`): for search hunks ≥200
  chars, whitespace and common characters are junked, so the similarity
  score, the 0.6 floor (D56), and the 0.05 uniqueness gap (D57) are all
  computed on a distorted metric. Reproduced: a true-0.891 near-match
  scored 0.593 (spurious not-found), and autojunk inverted a two-window
  ranking so the wrong window won with a gap that passed D57. Set
  `autojunk=False`; threshold calibration is meaningless without it.
- **Raise the default threshold.** 0.6 is below every published tool's
  floor (aider disables fuzzy entirely; Roo Code floors at 0.8, defaults
  exact). Reproduced wrong-hunk applications at 0.625, 0.924, and 0.957
  (sequential-edit invalidation — a stale search fuzzy-matching the hunk
  a prior edit rewrote). Raise the default to ≥0.8 or ship level 4 off by
  default until `allow_fuzzy` exists. The default-raise is a one-line
  change safe to cherry-pick ahead of Phase 7.
- **Preserve newlines and encoding.** `read_text()`/`write_text()`
  universal-newline translation silently converts CRLF files to LF
  (reproduced; `output.py:469`, `:429`), and CRLF carried in LLM replace
  text produces mixed endings. Read with `newline=''`, write with
  explicit newline and `encoding='utf-8'`, normalize replace-text endings
  to the file's dominant ending.
