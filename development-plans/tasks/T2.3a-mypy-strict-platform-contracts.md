## Background and Detailed Explanation

T2.3a flipped mypy `--strict` on for the contracts side of the platform
library. Forge had shipped strict typing all along; the packages
absorbed in T2.1 had not. This one covers the sandbox-light wire-model
surface (wire models, `persist_block`, `s3_blobs`, the Temporal connect
helper, DB helpers, constants, the `batch_jobs` schema) — the layer
every other package imports, so making its internals type-honest
protects all consumers downstream. Splitting the four strictness flips
into one task per package kept each independently mergeable.

The baseline was 18 strict errors in 5 files, mostly mechanical (missing
generic type args, untyped defs, a `TypeDecorator` type arg) plus two
substantive SQLAlchemy dialect issues in `db.py`. All 18 were fixed with
zero `type: ignore` comments — `UTCDateTime` gained a real
`TypeDecorator[datetime]` base, the event-listener params took
SQLAlchemy 2.0's public protocols, and the sqlite/postgres `Insert`
conflict was typed per dialect branch. The one override is
`ignore_missing_imports` for boto3/botocore, which ship no stubs.
Reader's note: this target was `libs/forge-contracts`, which Phase 3
(T3.4) folded into `sax_platform.contracts` — the gate came along with
it.

## Plan

*Written 2026-07-16. Target is today's `libs/forge-contracts` (the
task predates D98; the package becomes `sax_platform.contracts` in
Phase 3, which inherits this gate).*

Baseline measured: `mypy --strict src/forge_contracts` reports **18
errors in 5 files** (models, types, persist, db, s3_blobs) out of 9
checked. Mostly mechanical (`dict` type args, untyped defs,
`TypeDecorator` type arg, `no-any-return`); two substantive in
`db.py`: a mis-scoped `type: ignore[union-attr]` on line 68 and a
sqlite-vs-postgres `Insert` Callable incompatibility on line 95.

1. Add `[tool.mypy]` to `libs/forge-contracts/pyproject.toml`
   mirroring the root's strict block (`strict = true`, explicit warn
   flags, `files = ["src/forge_contracts"]`, `python_version = "3.14"`)
   so a bare `uv run mypy` works from the package directory — same
   per-package discipline as pytest.
2. Fix all 18 errors. Typing-only where possible; runtime behavior of
   the SPI surface must not change (the 100%-coverage suite from T2.2
   is the regression net). Narrow ignores with error codes only where
   SQLAlchemy's stubs genuinely can't express the dialect dispatch.
3. Wire the gate: `make typecheck` gains
   `cd libs/forge-contracts && uv run mypy`; CI's `lint` job gains the
   same step. T2.3b–d append their packages to both when they land.
4. Verify: member suite green (65 tests), forge + ocr suites green
   (both import the package), `make gates` green, PR CI green (the
   acceptance criterion).
5. Closeout: OVERVIEW debt row updated (mypy now forge +
   forge-contracts), CHANGELOG, TASKS.md, status.

## Development Notes

**2026-07-16 — baseline.** 18 strict errors in 5 of 9 files; full
listing captured in the plan. The package ships `py.typed` already, so
forge's own strict run has been checking its *signatures* all along —
this task makes its *internals* honest too.

**2026-07-16 — all 18 fixed with zero `type: ignore`s.** Highlights:
`UTCDateTime` now subclasses `TypeDecorator[datetime]` with real
base-class signatures + `@override`; db.py's event listener types its
params with SQLAlchemy 2.0's public Protocols (`DBAPIConnection`,
`ConnectionPoolEntry`), killing the old mis-scoped ignore outright;
the sqlite/postgres `Insert` conflict resolved by typing each dialect
branch inline (`stmt: SQLiteInsert | PostgresInsert`), dialect classes
imported under `TYPE_CHECKING` only, preserving the lazy-import
intent. One `[[tool.mypy.overrides]]` for boto3/botocore
(`ignore_missing_imports` — no stubs upstream; mirrors root's networkx
pattern, not a strictness loosening). `make gates` fully green:
mypy 56+9 files, 6/6 contracts, all five suites at their gates.
