## Problem

Generic plumbing is duplicated and scattered across the packages: three
`_LOCAL_RETRY` copies, ocr's own `persist.py`, 14+ point-of-use env reads,
and Temporal/DB/embedding helpers split between forge-contracts and
sax-llm — two package identities the one-lib topology adjudication
retires. The review also verified that psycopg does **not** auto-disable
prepared statements on Supabase's transaction pooler, so the engine
factory must handle that explicitly.

## Scope

`sax_platform.temporal` (connect_temporal with mTLS, run_worker scaffold
with sandbox passthrough + pydantic converter + graceful shutdown,
LLM_RETRY/DB_RETRY/IO_RETRY presets, `classify_llm_error` (typed SDK
exceptions first, message markers fallback, unit-tested),
`heartbeat_during`, persist_block + **public** retry presets);
`sax_platform.db` (engine factory with pooler detection — **set
`prepare_threshold=None` when port 6543**; run_migrations;
insert_or_ignore; UTCDateTime; s3_blobs); `sax_platform.embeddings`
(Embedder protocol + OpenAIEmbeddings, frozen EmbeddingResult,
base64-float32 codec); `sax_platform.config` (frozen pydantic-settings
groups — the only env readers; existing env names kept as aliases);
`sax_platform.logging`. Retire the forge-contracts and sax-llm package
identities; delete ocr/persist.py + the three `_LOCAL_RETRY` copies.

### Amendments (2026-07-08, capture sweep)

- **`run_worker` scaffold defaults:** set an explicit
  `max_concurrent_activities` sized for subprocess-heavy activities (today
  unbounded: N fan-out children × pytest runs), and a
  `graceful_shutdown_timeout` ≥ the longest sync-activity
  start_to_close (5 min) or per-app configurable — forge's hardcoded 30s
  (`worker.py:311`) cancels and re-pays in-flight LLM calls on every
  deploy.
- **Alembic env hardening when it moves into `sax_platform.db`:** add
  `render_as_batch=True` to both `configure()` calls (without it the
  first ALTER-shaped migration — likely T4.1's `batch_jobs` reduction —
  emits SQL SQLite cannot run, breaking the dev contract); enable
  `compare_server_default`/`compare_type` and reconcile 001_baseline's
  server_default declarations with the ORM's Python-side defaults so
  autogenerate is trustworthy; give the relocated alembic.ini no
  CWD-relative `sqlite:///forge.db` fallback (XDG path or fail-fast).
- **Serialize concurrent migrators:** `run_migrations` takes a Postgres
  advisory lock keyed on the version table (no-op on SQLite), or the
  deploy docs move migration to a pre-start step — two workers booting on
  a fresh DB currently race CREATE TABLE (`worker.py:109-121` +
  two-instance deploy).
- **Store hygiene:** engine factory sets an explicit SQLite
  `busy_timeout` pragma alongside WAL; `save_interaction`'s type-erased
  `**kwargs: object` becomes a typed payload (a misspelled column today
  surfaces as a runtime DB error inside a 20-attempt retry).
