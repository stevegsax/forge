**Last updated:** 2026-07-17

## Problem

Generic plumbing is duplicated and scattered across the packages: three
`_LOCAL_RETRY` copies, ocr's own `persist.py`, 14+ point-of-use env reads,
and Temporal/DB/embedding helpers split between forge-contracts and
sax-llm — two package identities the one-lib topology adjudication
retires. The review also verified that psycopg does **not** auto-disable
prepared statements on Supabase's transaction pooler, so the engine
factory must handle that explicitly.

## Scope

`sax_platform.temporal` (connect_temporal with mTLS, run_worker scaffold
with sandbox passthrough + pydantic converter + graceful shutdown,
LLM_RETRY/DB_RETRY/IO_RETRY presets, `classify_llm_error` (typed SDK
exceptions first, message markers fallback, unit-tested),
`heartbeat_during`, persist_block + **public** retry presets);
`sax_platform.db` (engine factory with pooler detection — **set
`prepare_threshold=None` when port 6543**; run_migrations;
insert_or_ignore; UTCDateTime; s3_blobs); `sax_platform.embeddings`
(Embedder protocol + OpenAIEmbeddings, frozen EmbeddingResult,
base64-float32 codec); `sax_platform.config` (frozen pydantic-settings
groups — the only env readers; existing env names kept as aliases);
`sax_platform.logging`. Retire the forge-contracts and sax-llm package
identities; delete ocr/persist.py + the three `_LOCAL_RETRY` copies.

### Amendments (2026-07-08, capture sweep)

- **`run_worker` scaffold defaults:** set an explicit
  `max_concurrent_activities` sized for subprocess-heavy activities (today
  unbounded: N fan-out children × pytest runs), and a
  `graceful_shutdown_timeout` ≥ the longest sync-activity
  start_to_close (5 min) or per-app configurable — forge's hardcoded 30s
  (`worker.py:311`) cancels and re-pays in-flight LLM calls on every
  deploy.
- **Alembic env hardening when it moves into `sax_platform.db`:** add
  `render_as_batch=True` to both `configure()` calls (without it the
  first ALTER-shaped migration — likely T4.1's `batch_jobs` reduction —
  emits SQL SQLite cannot run, breaking the dev contract); enable
  `compare_server_default`/`compare_type` and reconcile 001_baseline's
  server_default declarations with the ORM's Python-side defaults so
  autogenerate is trustworthy; give the relocated alembic.ini no
  CWD-relative `sqlite:///forge.db` fallback (XDG path or fail-fast).
- **Serialize concurrent migrators:** `run_migrations` takes a Postgres
  advisory lock keyed on the version table (no-op on SQLite), or the
  deploy docs move migration to a pre-start step — two workers booting on
  a fresh DB currently race CREATE TABLE (`worker.py:109-121` +
  two-instance deploy).
- **Store hygiene:** engine factory sets an explicit SQLite
  `busy_timeout` pragma alongside WAL; `save_interaction`'s type-erased
  `**kwargs: object` becomes a typed payload (a misspelled column today
  surfaces as a runtime DB error inside a 20-attempt retry).

## Plan

Design finalized 2026-07-17 after a three-agent exploration sweep of the
retiring packages, the duplicated plumbing, and the `sax_platform` target
state. Two premise corrections and one scope decision (all in Development
Notes 2026-07-17): plumbing lives **only** in forge-contracts (not "split
between forge-contracts and sax-llm"); this task retires **forge-contracts
only**; and the module layout follows **D89** (a `sax_platform.contracts`
sandbox-light layer), which overrides this task's flatter Scope list.

**Target structure:**

```
libs/sax-platform/src/sax_platform/
├── contracts/          # NEW sandbox-light layer (lazy __init__; no SDK/shell imports)
│   ├── constants.py    # ← forge_contracts/constants.py
│   ├── types.py        # ← forge_contracts/types.py (UTCDateTime)
│   ├── models.py       # ← forge_contracts/models.py (batch wire; T4.1 prunes signal models)
│   ├── batch_jobs.py   # ← forge_contracts/batch_jobs.py (read-only mirror)
│   ├── persist.py      # ← forge_contracts/persist.py (persist_block + PUBLIC PERSIST_RETRY)
│   └── s3_blobs.py     # ← forge_contracts/s3_blobs.py
├── temporal/           # NEW shell subpackage
│   ├── client.py       # ← forge_contracts/temporal.py (connect_temporal, build_tls_config)
│   ├── retries.py      # LLM_RETRY/DB_RETRY/IO_RETRY + classify_llm_error (NEW, SDK-free by type-name)
│   ├── heartbeat.py    # dedup forge/activities/_heartbeat.py + pbook copy
│   └── worker.py       # NEW run_worker scaffold (graceful_shutdown ≥300s, max_concurrent_activities)
├── db/                 # NEW shell subpackage
│   ├── engine.py       # pooler detection (prepare_threshold=None @6543) + WAL + busy_timeout
│   ├── migrations.py   # run_migrations w/ advisory lock keyed on version_table (no-op SQLite)
│   ├── ops.py          # insert_or_ignore, ensure_sqlite_parent, get_store_url, StoreConfigError
│   └── alembic.py      # shared configure(): render_as_batch/compare_type/compare_server_default
├── embeddings.py       # NEW — extracted from apps/pbook/src/pbook/embeddings.py
├── config.py           # NEW frozen pydantic-settings groups (env names kept as aliases)
├── logging.py          # NEW — unify forge/logging_config.py + pbook/log_config.py
├── llm/                # unchanged (T3.1–T3.3)
└── ocr.py              # unchanged (T3.3)
```

**Key design points** (rationale in the session plan artifact + Dev Notes):

- `persist_block` runs inside workflows and `contracts.models.resolve_batch_result`
  lazily imports `s3_blobs`, so both sit in the sandbox-light `contracts`
  layer — not in `temporal`/`db` as the flat Scope implied.
- `classify_llm_error` matches `type(exc).__name__` (seeded from forge's
  `non_retryable_error_types` + pbook's `_AUTH_ERROR_TYPE_NAMES`/markers) then
  message markers — **no `anthropic` import**, keeping `temporal` SDK-free.
- `run_worker` fixes the drain AC: `graceful_shutdown_timeout` default ≥300s +
  explicit `max_concurrent_activities`. forge + ocr adopt it; deeper
  class-based-activity DI stays in T3.6.
- `migrations.run_migrations` generalizes forge's advisory lock to key on the
  version table and **adds the lock ocr lacks**.
- `config.py` defines the reusable pydantic-settings **groups** and routes
  `sax_platform`'s own env reads; app-composite settings + elimination of the
  ~20 app-level point-of-use reads are **T3.6** (boundary flagged in notes).
- `embeddings` is a fresh extraction (no `Embedder` exists today); pbook is
  the only consumer (D92).

**Transition invariant:** forge-contracts stays installed and unedited until
its consumers are rewritten and its content moved; both `forge_contracts.*`
and `sax_platform.contracts.*` coexist through the consumer-rewrite waves, and
the package is deleted only in ST11.
