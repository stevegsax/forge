## Background and Detailed Explanation

The 2026-06-10 architecture review produced a lot of durable reasoning —
its findings, the ten contested points the merge adjudicated, and the
dispositions of the ideas it rejected — but that reasoning lived only in
plan files and machine-readable "wave JSONs" outside the repo. In
parallel, the `DECISIONS` log has not yet recorded the supersessions and
new decisions the migration enacted, and `WORKERS.md` lacks operating
guidance for the batch transport the migration shipped. This task is the
*completion* pass, run after the code lands: finish and verify the
in-repo record against what was actually built — not a from-scratch
write, since an initial review doc under `docs/reviews/` is produced in
the post-approval docs-only step.

**What "verify against what was built" now means.** The wave JSONs are
gone — the external `review-artifacts-2026-06-10/` copies were confirmed
missing (2026-07-08). So the completion pass checks the existing
[2026-06-architecture-review.md](../../docs/reviews/2026-06-architecture-review.md)
against the shipped code; anything not already distilled into the repo is
unrecoverable and must be re-derived from the code itself, never cited to
a source that no longer exists.

**The three deliverables.** (1) The consolidated review doc — both
plans' findings, their verdicts, the ten adjudications, and the
rejected-idea dispositions. (2) The remaining `DECISIONS` entries on the
sweep checklist (D3, D9 deferred-with-rationale, D10/D58, D13, D31–33,
D43–47, D75, D76–D82, the monorepo, composition roots, the knowledge
contract), with every superseded `Dxx` carrying a forward pointer — the
one hard acceptance gate. (3) A `WORKERS.md` operations section: the
drain / revert-and-replay default, the rule that `workflow.patched()` is
used only when paid batches are in flight, and the load-bearing warning
that a **workflow RESET cannot recover already-paid batch results** —
resetting past the submit point discards the pointer to a batch that was
already run and billed, an expensive trap for anyone reaching for RESET
as a routine recovery tool. Done when every superseded decision points
forward and markdownlint is clean.
