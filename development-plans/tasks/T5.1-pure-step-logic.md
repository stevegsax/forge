## Problem

`determine_transition` is deterministic logic executed as a Temporal
activity (`evaluate_transition`), violating "deterministic work should be
deterministic" — it costs an activity round-trip, worker registration, and
a mock in every workflow test. Failure-summary construction is copied
across five join sites, and result builders, persist-key construction, and
merge-resolution handling live inline in workflow code where they cannot
be unit-tested without Temporal.

## Scope

`forge/step_logic.py` (zero temporalio imports):

- `determine_transition` moves here, called inline — **the
  evaluate_transition activity, its registration, and its test mocks are
  deleted** (deterministic work stays deterministic).
- `failure_summary` (replaces five join copies).
- Result builders aggregating per-call LLMStats into run totals + a
  one-field `failure_kind` Literal on Task/Step/SubTaskResult.
- *(2026-07-08 sweep)* Result builders carry file contents exactly once:
  `TaskResult.output_files` keeps content; Step/SubTaskResult retain
  paths, digests, and stats after merge (today contents travel 3-4× —
  all_output_files + per-step + nested sub-task + resolved conflicts,
  `workflows.py:899,1320-1330` — and a large fan-out can approach
  Temporal's 2MB payload cap at completion, failing after all spend).
  Acceptance: a synthetic multi-hundred-KB fan-out's serialized
  TaskResult stays well under the cap.
- Persist-key builder (per-role occurrence counters).
- `merge_resolution(...) -> MergedFiles | MissingResolutions` union.
- Child-ID/timeout helpers.
- Update CLAUDE.md + ARCHITECTURE.md's universal-step text; record the
  D3-clause supersession.
