## Background and Detailed Explanation

Four verified-dead items sat in the tree, all delete-safe. The one
worth understanding is `build_interaction_dict` (`store.py`): it had
zero production callers, and resurrecting it would have been a trap — it
emits no `idempotency_key`, so its rows would be NULL-keyed, and
`insert_or_ignore` deduplicates on `idempotency_key` (NULLs never
conflict in SQLite or Postgres, so those rows could never dedupe). The
other three were plainly broken or orphaned: `scripts/basenames.py`
queried the `ocr_results` table that left with the OCR split;
`scripts/nushell/` was a README documenting a forge-level `ocr.nu`
module that never existed; and `boto3` was declared in forge's
dependencies but imported nowhere in forge source.

Two items carried re-decisions on the way. Deleting
`build_interaction_dict` also removed the row-builder that several
*unrelated* roundtrip and migration tests depended on, so those tests
were preserved by swapping in a small local `_interaction_row(...)`
factory rather than deleted (the deletion also orphaned two make-helpers
and six `forge.models` imports, all trimmed to keep ruff green). And
`boto3` was **moved**, not deleted: the task said to delete it because
forge-contracts declared it independently, but forge-contracts is now
gone and forge's own test suite imports boto3 directly for the moto S3
fixture — so `"boto3>=1.34"` moved from the runtime dependencies to the
dev group (runtime access stays transitive through sax-platform). A
straight deletion would have left the test import unprovisioned. The
original AC's "zero references to `ocr.nu`" was also stale as written:
the real `ocr.nu` legitimately lives at `apps/ocr/scripts/nushell/`, so
only the forge-level copy — a README for a module that never existed —
was removed.
