# T5.4 — Split the monolith

**Status:** DONE
**Phase:** 5 — Workflow consolidation (forge)
**Repos:** forge
**Depends on:** [T5.3](T5.3-single-gather-dispatch.md)
**Last updated:** 2026-07-27

## Problem

`workflows.py` is a 1,861-LOC monolith carrying the step pipeline three
times, the gather twice, and duplicated init/persist/dispatch blocks —
roughly 1,100 LOC of measured source duplication. With T5.1–T5.3 landed,
the workflow classes can collapse to thin drivers over the shared blocks,
and (after Phase 4) they should retain no signal-handling state at all.

## Background and Detailed Explanation

T5.4 was the payoff task for the three that preceded it, and by the time it ran
most of its 2026-06-10 premise had already been collected by them.

**The problem, as first written.** `workflows.py` was 1,861 lines: the step
pipeline three times, the gather twice, and duplicated init/persist/dispatch
scaffolding inside two large workflow classes — roughly 1,100 lines of
*measured* source duplication. A god-module that size is hard to read, hard to
test in isolation, and the place divergence bugs go unnoticed (the whole Phase-5
sequence exists because those duplicated copies drifted).

**What T5.1–T5.3 had already taken.** By 2026-07-27 the pipeline existed once
(`blocks/step.py`), the gather and the typed dispatch existed once
(`blocks/gather.py`, `blocks/dispatch.py`), the duplicated
init/persist/dispatch scaffolding had collapsed into `DispatchHostBase`, and
forge carried zero signal handlers. `workflows.py` was 894 lines. The owner
re-baselined the task rather than folding it into T5.5: what remained was
structural, and T5.5's harness rebuild already depended on the final layout.

**What T5.4 actually did.** It finished the reorganization and changed no
behavior. `workflows.py` became the `forge/workflows/` package — `task.py`
(`ForgeTaskWorkflow`) and `subtask.py` (`ForgeSubTaskWorkflow`), one driver per
module, with an `__init__` exporting the two classes so every importer stood
unchanged. `workflow_blocks.py`, the last module outside `blocks/` that held a
workflow shape, dissolved: the batch transport into `blocks/transport.py`, the
worktree helpers into `blocks/worktree.py`, and the `persist_block`
pass-through re-export deleted in favor of importing it from
`sax_platform.contracts.persist`. The exploration loop stopped being a method
on the task class and became `blocks/exploration.py`'s
`run_exploration_loop(host, ...)` plus a pure `format_exploration_context`. The
three loose ambient fields behind `DispatchHostBase.configure` became one frozen
`RunSettings`, so a run's lane, logging, and poll cadence are set once and
cannot be half-configured; full parameter-threading was evaluated and rejected,
because `_persist_occurrences` is genuinely mutable run state that must stay on
the host regardless.

**How it was known to be done:** every committed replay history passed the
Replayer **unregenerated** — reorganization cannot change a command sequence,
and Temporal registers a workflow by class name, so the proof is exact — and the
full suite went green-to-green with no test semantics changed (import paths and
comments only). The duplication AC closed on measurement rather than
re-earning: the 2026-06-10 monolith surface (`workflows.py` +
`workflow_blocks.py`) went 2,367 → 0 lines across T5.1–T5.4, replaced by two
thin drivers (816 lines of code across `task.py` and `subtask.py`) over seven
`blocks/` modules that each hold their shape once.

## Scope

`workflows.py` (1,861 LOC) → package:

- `task.py` (~150 LOC driver), `subtask.py` (~60 LOC), `blocks/`,
  exploration block as a free function.
- RunSettings (frozen) threaded as a parameter.
- Workflow classes end with **zero** signal state and no duplicated
  init/persist/dispatch blocks.

### Amendments (2026-07-27 — re-baseline after T5.1–T5.3, owner-adjudicated)

The 2026-06-10 premise is largely consumed: `workflows.py` is 894 lines
(was 1,861), the pipeline / gather / typed dispatch each exist once in
`blocks/` (T5.2/T5.3), the init/persist/dispatch dedup happened in
`blocks/host.py`'s `DispatchHostBase` (T5.3 ST3), and zero
`@workflow.signal`/`query`/`update` handlers exist in forge source
(verified 2026-07-27). The owner adjudicated keeping T5.4 standalone
with this re-baselined scope rather than folding it into T5.5:

- `workflows.py` → the `forge/workflows/` package: `task.py`
  (`ForgeTaskWorkflow`) and `subtask.py` (`ForgeSubTaskWorkflow`), one
  class per module; the package `__init__` exports the two classes so
  existing `from forge.workflows import ...` sites stand. The stale
  ~150/~60 LOC targets are replaced by structural criteria — after the
  exploration extraction the task driver still legitimately owns the
  plan-driving loop.
- `workflow_blocks.py` dissolves into `blocks/` — the reshuffle T5.2's
  plan and T5.3's ST8 both explicitly deferred to this task
  (`batch_submit_and_wait` and its failure taxonomy; the worktree
  remove/cleanup helpers). No re-export shims (the T5.3
  `FORGE_TASK_QUEUE` precedent: update the importers instead).
- The exploration loop and its formatting become free functions in
  `blocks/exploration.py`.
- A frozen `RunSettings` replaces the loose ambient trio
  (`_sync_mode` / `_log_messages` / `_poll_interval`) behind
  `DispatchHostBase.configure`.

## Plan

recorded in Development Notes; the implementation agent appends
Development Notes as it goes.)*

### Design decisions (settled)

1. **Package layout.** `src/forge/workflows.py` becomes
   `src/forge/workflows/` with `task.py` (`ForgeTaskWorkflow`),
   `subtask.py` (`ForgeSubTaskWorkflow`), and an `__init__.py`
   exporting exactly the two classes. This is standard package
   interface, not a compat shim — importers that already say
   `from forge.workflows import ForgeTaskWorkflow` stand unchanged;
   anything importing other names from `forge.workflows` moves to the
   real home. Each module carries its own
   `workflow.unsafe.imports_passed_through()` block trimmed to what it
   uses. Replay-safe by construction: Temporal registers workflows by
   class name, not module path.
2. **`workflow_blocks.py` dissolves** (the reshuffle deferred here by
   T5.2's plan decision 1 and T5.3's ST8 comment):
   `batch_submit_and_wait`, `BATCH_WAIT_FAILURES`, and
   `THINKING_MAX_TOKENS` → `blocks/transport.py`; `remove_worktree`
   and `cleanup_worktree_after_exception` → `blocks/worktree.py`; the
   `persist_block` pass-through re-export dies — its importers go to
   `sax_platform.contracts.persist` directly (the T5.3
   `FORGE_TASK_QUEUE` precedent). Known importers to update:
   `ingestion_workflow.py`, `activities/persist.py`, `presets.py`,
   `blocks/{step,dispatch,gather,host}.py`, tests. The import-linter
   contracts are package-level (verified 2026-07-27), so the moves are
   contract-neutral.
3. **Exploration as free functions.** `_run_exploration_loop` →
   `blocks/exploration.py:run_exploration_loop(host, ...)` (it
   dispatches through the host's exploration arm and executes
   `fulfill_context_requests`); `_format_exploration_context` → a pure
   `format_exploration_context` beside it. `task.py` builds its
   per-attempt explore hook and the planner-time exploration from
   these; `subtask.py` never explores (unchanged).
4. **`RunSettings`, the slim version.** A frozen dataclass
   (`sync_mode`, `log_messages`, `poll_interval`);
   `DispatchHostBase.configure(settings)` stores the one object and
   the three loose fields are deleted (accessors read the object, so
   block call sites do not churn). Full parameter-threading through
   every block seam was evaluated and rejected: `_persist_occurrences`
   is genuinely mutable workflow state that must stay on the host
   regardless, so threading the frozen trio would touch every
   signature while leaving the host ambient anyway — cost without the
   promised purity. The configure-before-dispatch coupling is bounded
   to the first line of both `run()` methods and is now a single
   assignment.
5. **Driver slimming is opportunistic, not a target.** Pure
   spec-assembly that reads clean as a builder may move to
   `step_logic.py` (zero-`temporalio` rule holds), but the plan-driving
   loop (`_drive_plan`), sanity cadence, and fan-out spec construction
   are legitimate driver logic — the stale ~150/~60 LOC numbers are
   not chased. Final module sizes are measured and recorded at close.
6. **Replay discipline: zero command changes.** Every move in this
   task is reorganization. The committed histories must pass
   UNREGENERATED; `tests/replay/regenerate.py` changes only its
   imports. If any step appears to require regeneration, that step is
   wrong — stop and re-derive.
