# T5.4 — Split the monolith

**Status:** NOT STARTED
**Phase:** 5 — Workflow consolidation (forge)
**Repos:** forge
**Depends on:** [T5.3](T5.3-single-gather-dispatch.md)
**Last updated:** 2026-06-10

## Problem

`workflows.py` is a 1,861-LOC monolith carrying the step pipeline three
times, the gather twice, and duplicated init/persist/dispatch blocks —
roughly 1,100 LOC of measured source duplication. With T5.1–T5.3 landed,
the workflow classes can collapse to thin drivers over the shared blocks,
and (after Phase 4) they should retain no signal-handling state at all.

## Background and Detailed Explanation

T5.4 is the payoff task for the three that precede it. With the pure
logic (T5.1), the step pipeline (T5.2), and the gather and dispatch
(T5.3) all extracted into shared blocks, what is left behind is a
`workflows.py` that no longer needs to be a monolith.

**The problem.** `workflows.py` is 1,861 lines: the step pipeline
three times, the gather twice, and duplicated init/persist/dispatch
scaffolding inside two large workflow classes — roughly 1,100 lines of
*measured* source duplication. A god-module this size is hard to read,
hard to test in isolation, and the place divergence bugs go unnoticed
(the whole Phase-5 sequence exists because those duplicated copies
drifted).

**The fix.** Once T5.1–T5.3 have pulled the shared behavior out, this
task finishes the job mechanically: split the module into a package
with a thin `task.py` driver (~150 LOC), a thin `subtask.py` (~60
LOC), the `blocks/` already built, and the exploration step as a free
function. `RunSettings` is frozen and threaded through as a parameter
rather than read from ambient instance state. Because Phase 4 already
deleted every forge signal handler (D88), the workflow classes come
out the other side with *zero* signal state and none of the duplicated
init/persist/dispatch blocks — they become thin drivers over the
shared blocks, nothing more.

**How you'll know it's done:** the ~1,100 LOC of duplication is gone
(measured, not estimated); every behavioral test still passes; and the
workflow classes carry no signal state and no duplicated blocks.

## Scope

`workflows.py` (1,861 LOC) → package:

- `task.py` (~150 LOC driver), `subtask.py` (~60 LOC), `blocks/`,
  exploration block as a free function.
- RunSettings (frozen) threaded as a parameter.
- Workflow classes end with **zero** signal state and no duplicated
  init/persist/dispatch blocks.

## Acceptance Criteria

- [ ] ~1,100 LOC of source duplication gone (measure).
- [ ] All behavioral tests green.
- [ ] Workflow classes end with **zero** signal state and no duplicated
  init/persist/dispatch blocks.
