# T3.5 — Forced-tool-use retirement

**Status:** DONE
**Phase:** 3 — `sax_platform` consolidation + structured outputs
**Repos:** sax monorepo (`apps/forge`, `libs/sax-platform`; pbook's
registry fork)
**Depends on:** [T3.1](T3.1-platform-llm-client.md),

**Last updated:** 2026-07-08

## Problem

With structured outputs covering both lanes (T3.1), forced tool use for
output shaping retires platform-wide — superseding D75's mechanism. The
string-keyed output-type registries (sax-llm's `_output_type_registry` and
pbook's fork) are module-level mutable state, and forge's session-autouse
conftest registry mirror has already drifted from worker.py. Explicit
frozen mappings at composition roots replace all of it.

## Background and Detailed Explanation

T3.5 is where the structured-outputs machinery T3.1 built actually
replaced the old mechanism at forge's and pbook's real call sites — and
where the last of the retired packages, `libs/sax-llm`, was deleted.
"Forced tool use" was the pre-structured-outputs way to coerce shaped
JSON out of the model by defining a throwaway tool and forcing its use;
recovering the right output class at parse time then required a
string-keyed registry lookup. Those registries were module-level mutable
state forked three ways — sax-llm's, pbook's, and a forge conftest
mirror that had already drifted from the real worker registration — and
they were replaced by frozen `OUTPUT_TYPES` mappings owned by each
composition root. With forge's LLM path moved onto `sax_platform.llm`,
the provider-neutral remainder of sax-llm folded in and the ~2,200-line
package was removed wholesale.

Two platform gaps had to close before any consumer could migrate. The
target client had **no thinking/effort support** on its methods yet
(that wire translation had been explicitly deferred from T3.2), and it
had **no stored-bytes path**: forge's transport (alive until T4.1)
stores each batch item's raw Message JSON at poll time and parses it
later, whereas the platform only knew how to classify a freshly streamed
result. So Wave 0 added thinking/effort to the sync methods and batch
builder, plus `classify_result_json` and `fetch_batch_result_lines` so
the poll path could keep storing verbatim bytes and classify them
afterward.

The important behavioral rule is about **retries on deterministic
bytes**. A refusal or a `max_tokens` truncation will not change if you
try to parse the same stored bytes again — the bytes are fixed. So on
the batch lane every stored-bytes outcome (refused, truncated, or schema
mismatch) is raised as a non-retryable `ApplicationError`, and
`LLMRefused`/`LLMTruncated` were added to the retry preset's
non-retryable set. This closes the acceptance criterion about never
burning local parse retries on identical stored bytes after a paid
up-to-24h round-trip. Note the deliberate asymmetry: `LLMSchemaMismatch`
stays *retryable* on the sync lane, where a fresh sample might genuinely
fix it, but not on the batch lane, where the bytes are already committed.

The buried gem is a **workflow-sandbox regression** that only surfaced
once the pieces were consolidated, invisible to each scoped agent. The
migrated batch modules imported `sax_platform.llm.batch` symbols at
module level, and `sax_platform.ocr`'s eager `mistralai` import became
newly reachable through the batch poll path's model flip — together
dragging the HTTP stack (urllib) into the Temporal workflow sandbox and
raising `RestrictedWorkflowAccessError` at import time. The fix restored
the lazy-SDK discipline sax-llm had quietly maintained (function-local
SDK imports, `mistralai` kept out of import time) and added a subprocess
guard test asserting that importing `forge.activities` pulls in no
anthropic/mistralai/httpx — so the same regression cannot silently
return.

## Scope

Forge's sync lane onto `complete[T]`; batch call sites onto the builder
(+ fetch-time `model_validate` with the call site's class); delete both
string-keyed registries (sax-llm `_output_type_registry` + pbook's fork) —
replaced by frozen OUTPUT_TYPES mappings at composition roots; delete
forge's session-autouse conftest registry mirror (already drifted from
worker.py).

**Also retires the sax-llm package identity** (moved here from
[T3.4](T3.4-platform-plumbing-modules.md) 2026-07-17): once forge's LLM path
runs on `sax_platform.llm`, the provider-neutral remainder that survives
(`models`, `protocol`, message types still consumed by forge/pbook) folds
into `sax_platform.llm` and `libs/sax-llm` is deleted — dropped from root
deps, `[tool.uv.sources]`, workspace members, `root_packages`, and the
independence contract. sax-llm holds no plumbing, so T3.4 leaves it in place;
retiring it here avoids relocating ~2,200 lines that this task deletes anyway.

### Two platform gaps must close first (Wave 0)

Exploration found the target client is not yet consumable as-is:

1. **No thinking/effort support.** `AnthropicLLM.complete*` and
   `build_batch_request` accept no thinking params and emit none on the wire;
   `ThinkingPolicy`'s docstring explicitly defers its wire translation to
   T3.5. Forge's planner/sanity/conflict-resolution/batch-submit sites pass
   `thinking_enabled`/`effort` today. → Add `thinking: ThinkingPolicy | None`
   to the sync methods + batch builder, porting `sax_llm.client.
   build_thinking_param` semantics (adaptive/disabled `thinking` param +
   `output_config.effort` merged alongside `format`).
2. **No stored-bytes path.** Forge's transport (alive until T4.1) stores raw
   per-item Message JSON at poll time and parses later; the platform only
   classifies streamed results. → Add to `sax_platform.llm.batch`:
   `classify_result_json(raw, *, output_type) -> Completion|Refused|
   Truncated|Mismatch` (reuse `_classify_succeeded_message`; cap from
   `usage.output_tokens` as the streamed path does) and
   `fetch_batch_result_lines(client, batch_id) -> [(custom_id,
   raw_message_json | BatchRequestFailed)]` so batch_poll keeps storing
   verbatim bytes.

Also Wave 0: add `"LLMRefused"`/`"LLMTruncated"` to `LLM_RETRY`'s
non-retryable names (`sax_platform/temporal/retries.py`) — refusal/truncation
are deterministic; `LLMSchemaMismatch` stays retryable on the sync lane
(sampling variance may fix it).

### Migration shape (Waves 1–2, parallel where files are disjoint)

**Forge sync sites (8)** — the 5-step forced-tool shape collapses to:
`split_provider(model)` (from `sax_platform.llm.tiers`; replaces
`parse_model_id`) → `llm.complete(messages=[user turn], system=...,
output_type=..., model=..., max_tokens=..., thinking=...)` →
`completion.output` already validated; `stop_reason`/tokens from `Completion`
fields (`extract_stop_reason` + raw-JSON re-parse die). `LLMRefused`/
`LLMTruncated` propagate → Temporal non-retryable via the updated preset.
Provider acquisition via a new interim `forge/llm_client.py::get_llm() ->
AnthropicLLM` (module-global cache + `reset_llm()`; T3.6 deletes it for
composition roots). Sites: activities/{llm,planner,extraction,
conflict_resolution,sanity_check,exploration,playbook_review}.py +
eval/judge.py.

**Forge batch path** — new `forge/output_types.py` holding frozen
`OUTPUT_TYPES: Mapping[str, type[BaseModel]]` (MappingProxyType; the 7 forge
types + conditional pbook `TranscriptAnalysisResult`), replacing both
registry lookups. `batch_submit` builds via platform `build_batch_request` +
`submit_batch`. `batch_poll` flips its lingua franca from `sax_llm.models`
poll shapes to the identical `sax_platform.ocr` family (T3.3 port), deletes
the mistral→sax_llm converter, and gains a small forge-side anthropic poll
adapter (status mapping ported from `AnthropicProvider.poll_batch`, raw lines
via `fetch_batch_result_lines`). `batch_parse` classifies stored bytes via
`classify_result_json` + `OUTPUT_TYPES[name]`: success → `ParsedLLMResponse`
(stop_reason from telemetry — AC #5's sibling AC records it); refused/
truncated/mismatch → `ApplicationError(non_retryable=True, type=...)` with
stop_reason in the message — **stored bytes are deterministic, so no outcome
is retryable (AC on burned retries)**. Worker's `_register_output_types`
deleted.

**pbook** — `workflow_steps/output_types.py` fork → frozen `OUTPUT_TYPES`
mapping (register/resolve/reset die); `llm_chat` moves onto
`complete[T]` (class from the mapping, result returned as
`tool_input=output.model_dump()` so workflow-side validation is unchanged);
refusal/truncation → non-retryable `ApplicationError` (extending the existing
`is_nonretryable_auth_error` pattern); `pbook/llm.py` re-types the provider
seam to the platform client behind a tiny local `SupportsComplete` Protocol
(set/get/reset globals survive until T3.6); worker's
`_register_llm_provider` becomes `AnthropicLLM(make_client())` — the
hardcoded retired `claude-3-5-sonnet-20241022` pin vanishes (model comes
per-call from tier-resolved `LLMChatInput.model`). pbook's own pyproject
drops `sax-llm` (lesson from T3.4: member manifests block workspace removal).

**Tests** — forge conftest gains `build_mock_llm` (stub with async
`complete` returning a canned `Completion` or raising typed outcomes),
written centrally BEFORE Wave 1 so parallel agents don't collide on
conftest; the 9 `build_mock_provider` test files + 3 tool_use-mock files
migrate; pbook's 4 mock files likewise. `build_mock_provider`/
`build_mock_message` + the drifted autouse registry fixture are deleted in
the cleanup wave.
