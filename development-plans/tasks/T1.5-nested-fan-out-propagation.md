## Plan

The bug: `_run_nested_fan_out` (workflows.py) duplicates the top-level
`_run_fan_out_step` gather but diverges — it (a) always resolves conflicts,
ignoring `resolve_conflicts`/D71 with no D27 terminal fallback, (b) hardcodes
`thinking=ThinkingConfig()`, and (c) fabricates a `ModelConfig()` overriding
only `reasoning` from `model_name` instead of using the parent's full
`model_routing`. Root cause: `SubTaskInput` never carried these three settings,
so the nested node had nothing to propagate.

Fix — make the nested path behave identically to the top-level path:

1. Add `resolve_conflicts` (bool), `model_routing` (ModelConfig), and
   `thinking` (ThinkingConfig) to `SubTaskInput`; delete the dead
   `worktree_path` field (verified unread via rg).
2. `_run_fan_out_step` (top level): propagate all three from the parent
   `ForgeTaskInput` into each child `SubTaskInput`.
3. `_run_nested_fan_out`: propagate all three into each nested child
   `SubTaskInput`, and rewrite its conflict block to mirror the top-level path:
   `if conflicts and input.resolve_conflicts:` → resolve using
   `model_routing=input.model_routing, thinking=input.thinking`;
   `elif conflicts:` → D27 terminal `SubTaskResult` (removing the worktree
   first, per D16, since a nested node owns its worktree); `else:` → merge.
