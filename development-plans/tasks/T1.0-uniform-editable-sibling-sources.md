## Development Notes

### 2026-07-15 — pbook's git-pin of sax-llm blocks a fully-editable switch

Discovered while running `uv lock` after switching all three siblings to
editable path sources: the lock **fails** with

```text
Requirements contain conflicting URLs for package `sax-llm`:
- file:///.../sax-llm (editable)
- git+https://github.com/stevegsax/sax-llm.git@v0.1.1
```

Root cause: pbook's own `pyproject.toml` declares
`sax-llm = { git = ".../sax-llm.git", tag = "v0.1.1" }` in its
`[tool.uv.sources]`. While pbook was itself a **git** dependency, uv ignored its
`tool.uv.sources`, so this pin was invisible and forge's matching git-tag pin
for sax-llm agreed with it (that is why the pre-migration lock resolved). The
moment pbook becomes an **editable path** dependency, uv reads pbook's
`tool.uv.sources`, and pbook's git-pinned sax-llm now conflicts with an editable
sax-llm declared in forge. uv 0.11.21 does **not** let the root project's source
override a transitive path-dependency's source; it errors on the ambiguity.

Verified the diagnosis by temporarily editing pbook's pyproject to make its
sax-llm source editable — forge then locked cleanly (exit 0) — then reverted
pbook (`git checkout pyproject.toml`; pbook left pristine, no commit).

Decision (within T1.0's forge-only scope — task Repos line is "forge (pyproject),
CLAUDE.md", and the deliverable is one forge commit):

- Switch `pbook` and `forge-contracts` to editable path sources.
- **Keep `sax-llm` on git tag `v0.1.1`.** This is the same commit pbook pins and
  the same commit `../sax-llm` HEAD points at (baseline: sax-llm HEAD == v0.1.1),
  so all consumers (forge, pbook, ocr) still resolve to identical sax-llm code —
  no drift today. A comment in `pyproject.toml` records why.

Rejected alternatives:

- Making sax-llm editable in forge **and** patching pbook to match: produces a
  forge lock that only resolves against a locally-patched pbook. A fresh checkout
  (or CI) with pbook's committed pyproject would hit the same conflict —
  non-reproducible. Also out of scope (would leave an uncommitted change in a
  separate repo that forge's single commit cannot carry).
- Committing a change to pbook separately: out of T1.0's stated repo scope; not
  authorized.

Follow-up: to make sax-llm truly editable everywhere, pbook must switch its own
sax-llm source to editable (a pbook-repo change), or wait for T2.1 which
collapses all repos into the `sax` monorepo where sources become
workspace-relative. Flagging for the migration owner.
