# T7.5 — One prompt builder

**Status:** NOT STARTED

**Repos:** forge

**Last updated:** 2026-07-08

## Problem

Prompt construction is copy-pasted into four builder grammars that must
be kept in sync by hand, and each one fabricates a fake TaskDefinition
(`task_mock`) to satisfy the shared signature. `build_error_section`
performs file reads inside what should be pure prompt-building logic,
violating the functional-core boundary the merged plan holds the
context engine to.

## Background and Detailed Explanation

Every mode forge runs — single-step, planned, fan-out, retry — builds
its LLM prompt through its own copy of the same assembly logic: four
*builder grammars* that must be kept in step by hand and have already
drifted. Each copy also fabricates a throwaway `TaskDefinition`
(`task_mock`) purely to satisfy a shared function signature it does not
really need. And `build_error_section` reads files from disk in the
middle of what is supposed to be pure prompt construction, violating the
project's Function Core / Imperative Shell rule (pure logic in the core,
I/O only at the edges).

**The fix.** Collapse the four grammars into one parameterized builder.
Replace the four `task_mock` fabrications with a small honest
`TaskFacts(task_id, description, target_files, domain)` — exactly the
fields the builder uses. Move `build_error_section`'s file reads out to
the shell, so the builder receives pre-read snippets and stays pure and
testable. Stable-first section ordering (D53) — the cache-friendly
layout that keeps the longest possible prompt prefix constant across
retries — is preserved.

**The buried gotcha: fence injection.** Today every piece of embedded
dynamic text — file contents, error/validation output, stored or
LLM-derived text — is wrapped in a bare triple-backtick fence with no
escaping (`context.py:242-247,383-385,172-174`). Any content that itself
contains a fence closes the block early, and everything after it is read
as prompt instructions rather than as data — a prompt-injection path
straight into the system prompt. The parameterized builder computes a
fence longer than the longest backtick run in the content (or escapes)
so embedded text can never break out of its block. (The playbook channel
is out of scope — it dies with T6.7.)

Done means golden-prompt tests for each mode, stable-first ordering held,
and a golden test whose input contains a triple-backtick fence rendering
without breaking the enclosing block.

## Scope

- The four copy-pasted builder grammars collapse into one parameterized
  builder.
- `TaskFacts(task_id, description, target_files, domain)` replaces the
  four `task_mock` TaskDefinition fabrications.
- `build_error_section`'s file reads move to the shell (pre-read
  snippets passed in).

  fences for all embedded dynamic text — file contents, error/validation

  so content containing a fence closes the block early and injects into
  the system prompt. Compute a fence longer than the longest backtick run
  in the content, or escape. (The playbook channel is out of scope — it
  dies with T6.7.)
