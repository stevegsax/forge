## Problem

A batch of small duplications and dead code across the three repos:

- forge keeps a local copy of `FORGE_TASK_QUEUE` (workflows.py:87) that
  duplicates `forge_contracts.constants`.
- ocr declares an unused sax-llm dependency and has a wrong `__init__.py`
  docstring.
- sax-llm carries a dead sync-OCR protocol surface
  (`supports_sync_ocr`/`call_ocr` in the protocol + both adapters).
- forge's scheduled re-extraction loop (`ForgeExtractionWorkflow` + the
  Schedule created in worker.py) re-extracts the same runs forever.

## Scope

  the local copy at workflows.py:87).

- Delete sax-llm's dead sync-OCR protocol surface
  (`supports_sync_ocr`/`call_ocr` in protocol + both adapters).
- Remove the forge-extraction Schedule creation from worker.py and delete
  `ForgeExtractionWorkflow` + its CLI command (the scheduled re-extraction

## Plan

Four independent items across three repos. Commit per repo (sax-llm, ocr,
forge — forge last, carrying this task file + TASKS.md + CHANGELOG.md).

1. **forge — `FORGE_TASK_QUEUE` dedup.** `src/forge/workflows.py` imports
   `FORGE_TASK_QUEUE` from `forge_contracts.constants` (the canonical source,
   `constants.py:19`) instead of defining the string literal locally. The name
   stays importable from `forge.workflows` (an incidental re-export used
   internally at the two child-workflow call sites and by the test suite).
   Repoint the production consumers — `cli.py` and `worker.py` — at
   `forge_contracts.constants` directly.
2. **ocr — drop unused sax-llm dep + docstring.** `rg` confirms nothing in ocr
   imports `sax_llm`. Remove `"sax-llm"` from `pyproject.toml` dependencies and
   the `[tool.uv.sources]` entry; `uv lock` (legitimate lock change, committed)
   - `uv sync`. Fix the stale dependency claim in `src/ocr/__init__.py`'s
   docstring (and the parallel line in `README.md`).
3. **sax-llm — delete dead sync-OCR surface.** Cross-repo `rg` (forge, ocr,
   sax-llm, pbook) confirms `supports_sync_ocr` / `call_ocr` are referenced only
   in sax-llm's own `protocol.py` + `anthropic.py` + `mistral.py`; no consumer
   anywhere, no test (sax-llm's OCR tests exercise the *batch* `/v1/ocr`
   endpoint, not these sync methods). Delete the property + method from the
   protocol and both adapters. Report resulting coverage (gate ≥85%).
4. **forge — kill the runs-re-extraction loop.** Delete
   `src/forge/extraction_workflow.py` (`ForgeExtractionWorkflow`), the
   `forge-extraction-schedule` creation in `worker.py`, the `forge extract` CLI
   command, and their tests. The extraction *activities*
   (`fetch_extraction_input`, `call_extraction_llm`, `save_extraction_results`)
   and models stay — they have direct unit tests and `save_extraction_results`
   is still called by `ManualPlaybookWorkflow`; Phase 6 (T6.7) owns their fate.
   Update live docs (README, `docs/user/playbooks.md`, `docs/requirements/*.feature`,
   models.py docstrings) so no live reference to the deleted symbols remains.

**2026-07-15 — implementation.**

- **Deadness verification (item 3):** `rg "supports_sync_ocr|\bcall_ocr\b"`
  across forge, ocr, sax-llm, and pbook (read-only) matched only sax-llm's own
  `protocol.py` / `anthropic.py` / `mistral.py` plus this task file and the
  handoff doc. sax-llm's 26 test mentions of "ocr" all exercise the *batch*
  `/v1/ocr` endpoint (`submit_batch` / `poll_batch`), not the sync methods —
