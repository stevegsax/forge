## Problem

1. **Defaults inversion.** `_submit_and_wait` defaults `sync_mode=True`
   (`cli.py:365`) while the CLI flag defaults to batch mode
   (`--sync/--no-sync` default False, `cli.py:614-619`). Any future
   caller relying on the helper's defaults silently gets sync mode,
   inverting the batch-first default the whole system is built on.
2. **Helper duplication.** `_submit_and_wait` (`cli.py:350-396`) and
   `_submit_no_wait` (`cli.py:399-446`) are ~45 identical lines differing
   only in `execute_workflow` vs `start_workflow`, and both re-declare 14
   keyword parameters mirroring `ForgeTaskInput` field-for-field —
   guaranteed drift.
3. **Double discovery.** `eval_planner` runs `discover_eval_cases` twice
   per invocation (`cli.py:1639` and again inside `_run_eval` at
   `cli.py:1553`) — duplicate directory I/O and a window for the case
   list to change between the count check and the run.

## Scope

- Align the helper defaults with the CLI's batch-first default (or make
  `sync_mode` a required parameter so no default exists to invert).
- Merge the two submit helpers behind one function with a wait flag;
  pass `ForgeTaskInput` (or a single kwargs dict) instead of 14 mirrored
  parameters.
- Discover eval cases once; pass the list through.

Coordinate note: Phases 5–6 change which CLI commands exist
(ingest/playbooks leave), but `run`/`eval-planner` and the submit helpers
survive — these fixes are not throwaway work.

## Acceptance Criteria

- [ ] Helper defaults match CLI defaults (test), or `sync_mode` has no
      default.
- [ ] One submit helper; rg shows no duplicated parameter mirror.
- [ ] One `discover_eval_cases` call per eval invocation.
