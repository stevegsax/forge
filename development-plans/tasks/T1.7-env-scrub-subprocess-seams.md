# T1.7 — Env scrub at model-influenced subprocess seams

**Status:** NOT STARTED
**Phase:** 1 — Stop the bleeding (current repos)
**Repos:** forge
**Depends on:** —
**Last updated:** 2026-07-08

## Problem

**Critical:** `validate.py` test commands and the `run_tests` exploration
provider execute model-influenced commands with the worker's full env (API
keys, DB URLs, TLS paths).

## Scope

- Explicit allowlist env dict (PATH, HOME, VIRTUAL_ENV, LANG, TMPDIR) at
  those two seams.
- **Amendment (2026-07-08):** drop root at the unit level too — the EC2
  systemd units run the worker as root with zero hardening, so the scrubbed
  env still executes model-influenced commands as root on the instance
  holding all platform secrets. Harden `deploy/systemd/forge-worker@.service`
  and `pbook-worker.service`: `User=forge`/`Group=forge`,
  `NoNewPrivileges=true`, `ProtectSystem=strict` (+ `ReadWritePaths=` for
  the app/data dirs), `ProtectHome=true`, `PrivateTmp=true`.

## Acceptance Criteria

- [ ] Test asserts `ANTHROPIC_API_KEY` (and `FORGE_DB_URL`) absent from the
      child env
- [ ] *(2026-07-08)* Worker runs unprivileged under the hardened units
      (verify `id -u` ≠ 0 from a validation subprocess on the deploy target)
