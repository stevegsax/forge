## Problem

The grimp import graph is built in the worker process against the
installed forge package, not the task's worktree — one of the review's
verified critical findings ("grimp analyzes the worker's installed
package, not the task worktree"). Context discovery therefore reflects
stale module structure, cannot see worktree-only changes, and cannot
work against a non-forge repo at all; graph failures fall back silently
with no signal in ContextStats. `module_to_file_path` compounds this
with CWD-relative checks that assume the worker's working directory.

## Scope

- Build the grimp graph in a subprocess with
  `PYTHONPATH={worktree}/{src_root}` (the ~20-line fix; fixes the
  critical worktree-drift finding and makes discovery work off-repo).
- `degraded: bool + degradation_reason` on ContextStats (logged, not
  silent).
- Repo map survives graph failure via file-walk fallback.
- Delete `module_to_file_path`'s CWD-relative checks.
- D31 amendment.
