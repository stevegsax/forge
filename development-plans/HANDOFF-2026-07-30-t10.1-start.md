## Owner rulings

Recorded in the T10.1 amendment (`6173166`), all binding:

- **The legacy prod data is junk — discard it.** No dump/restore, no
  row-count verification, no `REINDEX` of migrated data, no PG16→17
  data rehearsal. The cutover creates **fresh schemas on empty PG17
  databases** via the three migration chains. Discarded with the old
  instance: run/interaction spend history, the `batch_jobs` ledger,
  stored ocr results, pbook entries.
- **pbook is its own product** — first-class slug, own credential, own
  blast radius, registered via its own `datastore-registration.yaml`.
- **Namespaces are `<slug>-<env>`, not the bare slug.** Rationale
  recorded in the amendment: identical names across servers make an
  address mistake *silent* — a dev-configured process aimed at prod
  would find a namespace of the same name and poll production's queues.
  Distinct names fail closed. `forge` and `default` are retired and
  must not exist on any new server. **See item 3 — the external
  convention doc still says the opposite.**
- **ST5 (backup LaunchDaemon + one observed scheduled run) gates the
  cutover** per sax-datastores rationale §19.
- **Forge's own backup leg retires in the cutover change-set**, not
  before — until the profiles leave `:5434` it guards only junk, and
  the agent dies with the local-stack deletion anyway.
- **`deploy/local-stack` is deleted outright**, not shrunk.
- **The Temporal drain is separable and may precede the store cutover**
  (both servers run concurrently while legacy in-flight work finishes).
