## Owner rulings so far (binding)

1. **Order: T5.5 → T5.6** (review recommendation A2 reversed). Owner
   rationale, recorded verbatim in spirit: when a redesign is coming,
   restructure working code into the new shape first so subsequent
   functionality is built against good examples. The review's
   T5.6-first "live hazard" argument was withdrawn on scrutiny — with
   no live users the hazard is theoretical, and pattern-first wins.
2. **T5.6 preflight retries: three total attempts, no backoff,
   escalating context** (violations appended to the planner's retry
   context; optionally escalate thinking on the final attempt). Backoff
   was explicitly rejected: preflight failures are semantic, not
   transient — the transport layer already owns transient retry, and
   backoff on the batch lane would stretch a doomed plan by hours.
3. **T5.5 scope additions:** the test-file split (per-mode files +
   `tests/support/workflow_harness.py`) folds in; `pytest-xdist` lands
   as a dev dependency (the AC is demonstrated, not asserted); the four
   promised replay histories (planned-step, nested gather, exploration,
   sanity) become hard ACs with three stretch (conflict resolution,
   sync planner, worktree-reset retry).
4. **Delegation is gated on the migration guide.** The owner requires
   explicit written context for code authors and reviewers before any
   code-writer batch:
   [tasks/T5.5-harness-migration-guide.md](tasks/T5.5-harness-migration-guide.md)
   is that document and is **binding** — decisions D1–D10, good/bad
   example pairs, the watch-out list, the delegation boundary (§5), the
   internal sequencing (§6), and the per-batch reviewer checklist (§7).

   note.
