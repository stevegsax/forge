# Architecture Review — June 2026

Adversarial review of pbook and its ecosystem (sax-llm, ocr, forge integration, skill-pbook),
performed 2026-06-09. There is no deployed base, so backward compatibility was explicitly out
of scope. This document is the standing record: verified findings, the target architecture,
and the phased migration order. Each phase is planned and executed separately. The other
design documents (OVERVIEW, DECISIONS, DATA_MODEL, WORKFLOWS, CLI, INTEGRATION) describe the
*target* architecture; until the relevant phase lands, the code differs from them — this
document's findings record the pre-review state, and the migration order tracks what changes
when.

Constraints every change must preserve: functional core / imperative shell, testability over
performance, and the Python quality bar (mypy strict as a build gate, no module-level mutable
state, dependency injection by parameter, frozen dataclasses, parse-don't-validate). The shop
is one developer — every component must justify its maintenance cost.

## Decisions

| Decision | Outcome |
| --- | --- |
| Repo topology | One `sax` uv-workspace monorepo: `libs/sax-platform` + `apps/{pbook,ocr,forge}`; sax-llm and forge-contracts absorbed and retired |
| Temporal's role | Durable jobs only (ingestion, curation). CRUD/retrieval/export become synchronous library calls. Workflow-as-RPC is banned ([TEMPORAL_PATTERNS.md](TEMPORAL_PATTERNS.md)) |
| Cross-service calls | Ingestion ownership inverts to pbook; forge coupling deleted. Temporal Nexus evaluated and rejected — nothing left to mediate |
| Structured output | Anthropic first-class structured outputs (`client.messages.parse`); forced-tool-use and both string-keyed output-type registries deleted |
| Extraction models | Extraction = GENERATION tier (sonnet); validation judge = CLASSIFICATION tier (haiku). Message Batches rejected at current volume (revisit > ~500 sessions/month) |
| Idempotency | Deterministic `origin_hash` + ON CONFLICT; cosine thresholds demoted to match-or-attach policy only |
| Entry lifecycle | `probation → active → stale/superseded/rejected` state machine; nothing hard-deletes; consolidation survivors re-earn trust (probation, zeroed counters); backfilled actives get a one-time judge sweep |
| Retrieval | Hybrid lexical (tsvector) + semantic (halfvec pgvector) + tags, fused by RRF in one pure scoring function |
| Feedback | Event log + explicit human-confirmed signals + served-never-helpful decay; no synthetic outcome pipeline |
| Evals | Hand-rolled pytest suites (extraction goldens, judge calibration, retrieval goldens); model pins move only on green paired-delta runs |
| Embeddings | text-embedding-3-small retained; halfvec storage; model/dim metadata columns; re-evaluate only on retrieval-eval evidence |
| Tags | 5 closed namespaces kept; values pattern-validated and normalized (never save-failing); demoted from retrieval gate to capped ranking boost |

## Part 1 — Findings

Verified against code 2026-06-09; line numbers reference that snapshot.

### Structural

1. **Workflow-as-RPC everywhere.** 16 one-activity wrapper workflows in
   `src/pbook/workflows/cli_ops.py`; every CLI command except `migrate` and `skill-prompt`
   requires Temporal plus the running worker (`cli.py` module docstring states this by
   design). Temporal guidance names CRUD-via-workflow an antipattern.
2. **SKILL.md contradicted the code** (skill-pbook `pbook/SKILL.md`): it documented
   `list`/`get`/`add`/`approve`/`feedback`/etc. as "direct DB reads/writes — no worker
   required", but all ten route through `_execute_workflow()` and hard-require the worker.
   (Corrected in skill-pbook as part of this review.)
3. **Agent hot-path latency.** `pbook search` = uvx git fetch + CLI startup + Temporal
   connect + four sequential activities with two-pass DB access (`fetch_candidates` →
   `llm_embed` → `compute_similarities_by_id` → `score_and_pack`).
4. **Bidirectional forge↔pbook coupling.** Forge's ingestion workflows call pbook's
   `ExtractionWorkflow` and activities cross-queue, import pbook pure functions, and git-tag-pin
   pbook v0.2.1; pbook's CLI submits `BatchIngestionWorkflow` to forge's queue and seeds
   `running` session rows that stay `running` forever if the forge-side workflow dies (no
   timeout or reconciliation).
5. **forge carries a diverged full copy of sax-llm** (`forge/src/forge/llm_providers/` +
   `llm_client.py`) with zero importers — dead code that received the ecosystem's only
   mypy-strict work.
6. **Model config has rotted.** The worker registers retired `claude-3-5-sonnet-20241022` as
   the default provider (`worker.py:106`); the tier registry is copy-pasted between pbook and
   forge and has already drifted (GENERATION: `sonnet-4-6` vs `sonnet-4-5-20250929`).

### Quality-bar violations (the shop's own rules)

1. Module-level mutable singletons: `pbook.llm._provider`, `pbook.embeddings._client`,
   `pbook.store._engines`, `sax_llm.client._client`. Tests monkeypatch them.
2. No mypy outside forge; zero CI in all five repos; no `.python-version` anywhere. pbook and
   sax-llm ship `py.typed` while never being type-checked. The store hands out
   `dict[str, Any]` domain objects.
3. Two parallel string-keyed registries, twice (providers; output types). A typo becomes
   `KeyError` at activity runtime; forge and pbook both register the name "ExtractionResult"
   for different classes.

### Reliability

1. `ExtractionWorkflow` loops per experience with no error isolation — the first failure
    kills the remaining batch items (`workflows/extraction.py:68-136`).
2. Idempotency is cosine-similarity thresholds (0.85 entries / 0.92 sources, hardcoded).
    Retries after embedding drift duplicate entries. No deterministic keys (ocr uses uuid5;
    pbook has none).
3. `chunk_transcript()` exists but the production forge path never chunks — whole transcripts
    go to the LLM with no size guard.
4. Maintenance consolidation: four sequential activities per cluster; the save/prune split is
    non-atomic (a crash between them loses provenance); 45% test coverage; consolidated output
    lands pre-approved, bypassing the quality gate.
5. No replay tests, no migration tests, no workflow-versioning posture.

### Knowledge quality (the product)

1. The "better to extract nothing than mislead" bar exists only as prompt text. Zero evals —
    no golden set, no judge calibration, no retrieval metrics. Published agent-memory research
    puts LLM-extracted lesson noise around 30% without a validation gate.
2. Retrieval is hierarchical, not fused: with a free-text query, cosine similarity is primary
    and tag overlap a tiebreaker — feedback counters are ignored on this path; without a
    query, ranking is tag-only and zero-tag-overlap entries can never surface (`score_entry`
    returns 0.0 and `get_entries_by_tags` gates the candidate pool). Entries with NULL
    embeddings are silently invisible to semantic search. There is no lexical search at all;
    pure-vector retrieval is a documented dead end in 2025-26 agent-memory research.
3. Feedback is bare counter increments (`store.py:564-570`); helpfulness affects only the
    no-query path, gated at `retrieval_count >= 3`; nothing ties served entries to outcomes.
4. No entry lifecycle: `needs_review` and `rejected` booleans plus a CLI hard-delete coexist —
    illegal states are constructible and `pbook reject` destroys audit history.
5. Embeddings are full-precision `vector(1536)`; the dimension is hardcoded in three places;
    there are no model/dimension metadata columns. `halfvec` halves storage at ~99% recall.

### Documentation

1. The design documents had drifted from the code: SQLite-era APIs in INTEGRATION.md,
    duplicated and garbled sections in DATA_MODEL.md, a contradictory entry-type story, and an
    undocumented `feedback` command. (They remain accurate to the *current* system where noted;
    each migration phase updates them.)

## Part 2 — Target architecture

Ordering is load-bearing: R1's monorepo makes every later cross-cutting change a single atomic
commit, and R1's LLM client is what R2's ingestion and R3's validation gate call.

### R1 — One `sax` uv-workspace monorepo + `sax_platform` library

New repo `sax`: `libs/sax-platform` plus `apps/pbook`, `apps/ocr`, `apps/forge`. sax-llm and
forge-contracts are absorbed into the platform library and their repos archived with pointer
READMEs (full history preserved in the archives; import via shallow subtree to keep clones
small for uvx). One `.python-version` (3.14 if temporalio/psycopg/pgvector/pymupdf wheels
allow — verify first, else 3.13), one `uv.lock`, one CI workflow (ruff + mypy strict, staged
per package + pytest with a pgvector service container). The skill invocation becomes
`uvx --from "git+https://github.com/stevegsax/sax.git#subdirectory=apps/pbook" pbook <cmd>`
(verify end-to-end early; escape hatch for clone latency: publish a pbook wheel).

`sax_platform` owns exactly the concerns currently implemented two or three times:

- `llm/` — `AnthropicLLM(client)` built on first-class structured outputs:
  `complete[T: BaseModel](..., output_type: type[T]) -> Completion[T]` via
  `client.messages.parse`; `complete_schema(...)` (JSON-schema dict path for generic
  activities); `complete_text(...)`. Frozen `Completion[T]` carries token/cache telemetry.
  `MistralOcr` keeps only what production uses (OCR batch + sync call); Mistral chat support
  is deleted. One `tiers.py` (CapabilityTier / ModelConfig / resolve_model) with current model
  aliases. Caller-side `model_validate` remains the authoritative schema gate.
- `embeddings/` — `Embedder` protocol + `OpenAIEmbeddings(client, model)` returning a frozen
  `EmbeddingResult(vector, model, dim)`; pure base64-float32 codec.
- `temporal/` — `connect_temporal()` chokepoint; `run_worker()` scaffold (sandbox passthrough,
  pydantic converter, graceful shutdown); retry presets (`LLM_RETRY`, `DB_RETRY`); typed
  `classify_llm_error()` (SDK exception types plus message-marker fallback, unit-tested);
  `heartbeat_during`.
- `db/` — engine factory with pooler detection; `run_migrations`; `insert_or_ignore`.
- `config.py` — frozen pydantic-settings groups; existing env names kept as validation
  aliases; env is read only here; missing required config crashes startup.
- `logging.py`; `contracts/` (forge-contracts wire models and S3 blob helpers, absorbed).

Singletons die. Activities become methods on frozen activity classes constructed at each
composition root (`Worker(activities=[acts.method, ...])` — Temporal's sanctioned DI). Both
string-keyed registries are deleted: pbook's activities are typed per purpose (the output
class is in the signature, mypy-checkable); forge's generic path carries
`model_json_schema()` in the activity input. Tests construct activity classes with fakes
satisfying the protocols — no monkeypatching module globals. ocr receives `MistralOcr` via DI
(replacing `get_provider_by_name("mistral")`). Local Temporal state is drained before any
activity-input shape change.

### R2 — Right-size orchestration: pbook becomes library-first; two workflows survive

Delete 20 of 22 workflows. CRUD, retrieval, and export become synchronous functions in
`pbook/service.py` over a frozen `AppContext(settings, engine, embedder | None)` built once at
`__main__` entry (never module-cached). A missing `PBOOK_DATABASE_URL` raises `ConfigError`,
which the CLI maps to the existing `db_disabled` envelope. Golden `--json` characterization
tests are recorded for every command *before* the refactor and stay green through it — the
skill's parsing contract is pinned.

Retrieval fast path: one embedding call + one SQL statement (similarity computed via `<=>`
inside the candidate query — the HNSW index already exists) + pure rank/pack. Budget: p50 < 1s,
p95 < 2s. Keyless degraded mode: `ORDER BY ts_rank_cd(search_tsv, websearch_to_tsquery(:q))
DESC, tag_overlap DESC`, with `"degraded": "no_embedding_key"` in the envelope — search never
hard-fails on a missing key. No query-embedding cache initially; the named escape hatch is a
cache owned by the `Embedder` instance, never module-level.

Ingestion inverts: pbook owns transcripts end-to-end. `IngestWorkflow` runs per session with
deterministic id `pbook-ingest-{session_id}`; its first activity writes the `running` row (no
more CLI-seeded orphans); a workflow-level error handler records `error`; a sweep flips rows
stuck `running` > 48h. Transcript analysis is one synchronous structured-output activity with
heartbeat. Transcripts cross the activity boundary as `{path, session_id}` (claim-check by
path; S3 via the platform contracts module is the documented posture if workers ever leave the
dev machine). Forge's ingestion workflows, conditional pbook imports, and pbook dependency are
deleted in the same atomic commit.

Durability hardening: per-experience try/except with per-item outcome records; deterministic
`origin_hash = sha256(session_id + experience_hash + normalized_title)` (nullable for legacy
rows, globally unique, `ON CONFLICT DO NOTHING`); the 0.85/0.92 cosine thresholds remain only
as cross-session match-or-attach policy. Documented limitation: re-ingesting a *corrected*
experience requires purge-then-reingest. CurationWorkflow (R3) runs as a weekly Temporal
Schedule (fixed id; already-exists ignored) plus `pbook curate` on demand. Replay tests with
committed histories live under `tests/replay/` with a one-command regeneration target.

### R3 — Knowledge quality: lifecycle, extract+judge, hybrid retrieval, evals

**Lifecycle.** `status ∈ {probation, active, stale, rejected, superseded}` (CHECK-constrained)
plus `status_reason`, `status_changed_at`, `superseded_by_id`, `last_validated_at`,
`rejected_by ∈ {validator, human, curation}` replaces the boolean pair and the hard-delete.
Transitions live in one pure function `lifecycle.transition(current, event) -> EntryStatus |
IllegalTransition` with exhaustive `match` + `assert_never`. Backfill rules: `rejected=true`
wins over `needs_review=true`; backfilled actives get a one-time judge sweep (failures →
probation for triage) instead of grandfathering under the old bar. Nothing hard-deletes;
`pbook purge` becomes an explicit admin command. Staleness is a pure function with three
triggers — age (entries carrying `lib:`/`project:` tags: 270 days; pure `lang:`/`domain:`
entries: 540 days; constants in a frozen `StalenessConfig` with documented rationale), signal
(`harmful >= 2` and `harmful > helpful`), dead weight (served ≥ 10 times, zero helpful) — plus
explicit `pbook invalidate <id> --reason`. Stale entries are flagged for
`pbook review --stale`, never deleted.

**Extract + judge.** Extraction moves to the GENERATION tier (sonnet) in code — quality is the
product, and the cheapest model currently does the highest-stakes job. A separate validation
judge (CLASSIFICATION tier, one call per experience batching its candidates) applies four
binary checks: grounded-in-resolution, specific, non-generic, actionable. Failures are stored
as `rejected_by='validator'` rows — auditable and minable as eval goldens. Survivors insert as
`probation`; the first human-confirmed helpful feedback promotes to `active`. Consolidation
survivors also enter probation with zeroed counters (provenance lives in reparented
`entry_sources`). The static extraction system prompt becomes a constant with `cache_control`;
experience payloads move to the user message (caching pays during multi-session ingestion
runs — it is not a blanket discount).

**Hybrid retrieval.** Migration adds a `search_tsv` generated tsvector column + GIN index;
embeddings convert to `halfvec(1536)` (HNSW rebuilt with `halfvec_cosine_ops`) with
`embedding_model`/`embedding_dim` columns; the migration itself preflights pgvector ≥ 0.7
(halfvec) and ≥ 0.8 (iterative scans) and refuses to run otherwise. Candidates are the union
of lexical top-50, semantic top-50 (status-filtered in SQL with `hnsw.iterative_scan`
enabled), and tag top-50. One pure function `ranking.score_candidates(...)` with a frozen
`ScoringWeights` dataclass does all scoring: an RRF base (k=60, the standard constant) over
the lexical and semantic rank lists, multiplied by bounded factors for tag overlap (capped),
mode alignment (CREATE/FIX), feedback ratio (gated at ≥ 3 retrievals), and probation (×0.7);
scores clamp at ≥ 0 and both branches' ranges are documented. Zero-tag-overlap entries surface
via the lexical/semantic lists by construction. Packed probation entries carry
`"status": "probation"` so consumers see confidence. Tags keep their five closed namespaces;
values are pattern-validated (`^[a-z0-9][a-z0-9-]{0,30}$`) and normalized via an alias map,
never save-failing; tags are demoted from retrieval gate to capped ranking boost.

**Feedback.** Two event tables: `pbk_retrieval_events` (query, tags, mode, served ids, client,
session_id) and `pbk_feedback_events` (entry, polarity, source, session_id, with
`UNIQUE(entry_id, session_id, polarity)`); `session_id` is the Claude Code session UUID
supplied by the skill — a distinct namespace from ingestion sessions. Attribution policy,
stated honestly for a one-developer shop: explicit human-confirmed feedback plus
served-but-never-helpful decay; no synthetic outcome pipeline. Poisoning bounds: per-session
idempotency, human confirmation before recording, and feedback can demote or flag but never
auto-reject.

**Evals as pytest.** Hand-rolled (~150 lines of pure assertions; no eval-framework
dependency). `tests/evals/` is marked `@pytest.mark.eval` and excluded from the default run;
`make evals` runs it:

- Suite A, extraction goldens: 30 cases growing toward 100 (10 negative cases that must
  extract zero entries — the quality bar as a failing test; 20 positive cases with key-phrase
  and count bounds; grown by mining validator rejections). Gates: negatives 100%, positives
  ≥ 80%. This is a model/prompt regression gate, not a tuning loop.
- Suite B, judge calibration: ~40 hand-graded cases including 10 generic-advice traps (the one
  irreducible human task, ~2 hours; re-run only on judge model/prompt change). Gates: ≥ 85%
  agreement, 100% trap rejection.
- Suite C, retrieval goldens: ~80-entry frozen corpus with pre-computed embeddings committed
  to the repo (embedded once by a PEP-723 helper script; zero API calls at test time) and ~50
  labeled queries across tag-only / query-only / mixed / FIX / CREATE / zero-tag-overlap.
  Gates: recall@5 ≥ 0.8, MRR ≥ 0.6.
- Model upgrades: pins move only on green paired-delta runs (old vs new), with the delta table
  in the commit message. Embedding-model changes additionally re-embed the frozen corpus.

### R4 — Truth pass

Rewrite OVERVIEW/DATA_MODEL/WORKFLOWS/CLI/INTEGRATION to the new reality; keep
[TEMPORAL_PATTERNS.md](TEMPORAL_PATTERNS.md) current; update skill-pbook SKILL.md (worker
requirements, env vars, degraded mode, probation annotation, uvx pin). Follow-up: harmonize
ocr to the house pattern (shared retry presets; timer-loop poll replacing its dependency on
forge's batch poller signals).

## Migration order

Each step lands green before the next starts.

1. **R1.1** Wheel check → pin `.python-version`; create the `sax` workspace (shallow subtree
   imports); single `uv.lock` (timeboxed; contingency: relax forge's heavy pins); CI online
   (mypy strict gates forge only at first).
2. **R1.2** Build `sax_platform` (strict from day one), including `AnthropicLLM` on
   `messages.parse` with mocked-transport tests. No consumers ported yet.
3. **R1.3** Port pbook → ocr (MistralOcr via DI) → forge (delete `llm_providers/`,
   `llm_client.py`, tier copy; two commits: import swap, then class-based DI). Retire the
   sax-llm and forge-contracts members; archive the old repos; verify the uvx subdirectory
   invocation end-to-end; flip mypy strict per package as each ports.
4. **R2.1** Golden envelope tests → `service.py` + `AppContext` → delete the 20 workflows →
   single-pass retrieval SQL + degraded mode.
5. **R2.2** `IngestWorkflow` (ownership inversion, per-item isolation, `origin_hash` migration
   with pgvector preflight and the first migration test); delete forge's ingestion side in the
   same commit; CurationWorkflow shell + Schedule.
6. **R3.1** Pure core first (`lifecycle.py`, `ranking.py`, exhaustive parametrized tests) →
   the destructive lifecycle/hybrid migration (status machine, `search_tsv`, halfvec, metadata,
   event tables; backfill + one-time judge sweep).
7. **R3.2** Extract+judge pipeline; hybrid retrieval wired; feedback events; CLI additions
   (`invalidate`, `review --stale`, `purge`); skill update.
8. **R3.3** Eval harness (suites A/B/C, `make evals`, CI wiring); judge calibration grading.
9. **R4** Docs truth pass; ocr follow-up.
