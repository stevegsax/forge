# Data Model

*Describes the target architecture adopted in the June 2026 review; implementation is phased —
see [REVIEW-2026-06.md](REVIEW-2026-06.md).*

## Database schema

PostgreSQL (Supabase-hosted), all objects in the `pbook` schema and prefixed `pbk_`. Managed by
Alembic with version table `pbook.pbk_alembic_version`, so pbook's migration chain never
collides with another tenant of the same database.

### Migration posture

There is no deployed base, so the target schema arrives as a **single destructive migration**
from the current schema. The migration preflights the installed pgvector version and refuses
to run unless it is **≥ 0.7** (`halfvec`) and **≥ 0.8** (iterative index scans).

Backfill rules for existing rows (the old `needs_review`/`rejected` booleans are replaced by
`status`/`status_reason`):

1. `rejected = true` wins over `needs_review = true` → `status = 'rejected'`.
2. Otherwise `needs_review = true` → `status = 'probation'`.
3. Otherwise → `status = 'active'`, followed by a **one-time judge sweep**: backfilled actives
   are re-checked by the validation judge instead of being grandfathered under the old bar;
   failures drop to `probation` for triage.

### `pbk_entries`

One table holds both entry types; `entry_type` is the discriminator. The `api_doc` type is
removed (see [Entry types](#entry-types)). Removed columns: `needs_review`, `rejected`,
`rejection_reason` — replaced by the `status` machine below.

```sql
CREATE TABLE pbook.pbk_entries (
    id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title             TEXT NOT NULL,
    content           TEXT NOT NULL,
    entry_type        TEXT NOT NULL CHECK (entry_type IN ('pitfall', 'curated')),
    source_project    TEXT NOT NULL DEFAULT '',
    source_task_id    TEXT NOT NULL DEFAULT '',
    status            TEXT NOT NULL DEFAULT 'probation'
                      CHECK (status IN ('probation', 'active', 'stale',
                                        'rejected', 'superseded')),
    status_reason     TEXT,
    status_changed_at TIMESTAMPTZ,
    rejected_by       TEXT CHECK (rejected_by IN ('validator', 'human', 'curation')),
    superseded_by_id  BIGINT REFERENCES pbook.pbk_entries(id),
    last_validated_at TIMESTAMPTZ,
    origin_hash       TEXT UNIQUE,  -- sha256(session_id + experience_hash +
                                    -- normalized_title); NULL for manual/legacy entries
    helpful_count     INTEGER NOT NULL DEFAULT 0,
    harmful_count     INTEGER NOT NULL DEFAULT 0,
    retrieval_count   INTEGER NOT NULL DEFAULT 0,
    created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    embedding         HALFVEC(1536),                -- text-embedding-3-small
    embedding_model   TEXT NOT NULL DEFAULT 'text-embedding-3-small',
    embedding_dim     INTEGER NOT NULL DEFAULT 1536,
    search_tsv        tsvector GENERATED ALWAYS AS
                      (to_tsvector('english', title || ' ' || content)) STORED
);
CREATE INDEX ix_pbk_entries_embedding      ON pbook.pbk_entries
    USING hnsw (embedding halfvec_cosine_ops);      -- ANN cosine search
CREATE INDEX ix_pbk_entries_search_tsv     ON pbook.pbk_entries USING gin (search_tsv);
CREATE INDEX ix_pbk_entries_source_project ON pbook.pbk_entries (source_project);
CREATE INDEX ix_pbk_entries_entry_type     ON pbook.pbk_entries (entry_type);
CREATE INDEX ix_pbk_entries_status         ON pbook.pbk_entries (status);
```

`origin_hash` is the deterministic idempotency key for ingestion writes (insert is
`ON CONFLICT (origin_hash) DO NOTHING`). The cosine thresholds (0.85 entry-match, 0.92
source-dedup) remain only as cross-session match-or-attach policy — never retry protection.

### `pbk_entry_tags`

Tags normalized out of the entry row (matching is a JOIN). Unchanged from the current schema.

```sql
CREATE TABLE pbook.pbk_entry_tags (
    id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    entry_id BIGINT NOT NULL REFERENCES pbook.pbk_entries(id) ON DELETE CASCADE,
    tag      TEXT NOT NULL,                          -- namespaced, e.g. "lang:python"
    UNIQUE (entry_id, tag)
);
CREATE INDEX ix_pbk_entry_tags_tag      ON pbook.pbk_entry_tags (tag);
CREATE INDEX ix_pbk_entry_tags_entry_id ON pbook.pbk_entry_tags (entry_id);
```

### `pbk_entry_sources`

Provenance: which session/experience produced or matched an entry. Consolidation **reparents**
these rows onto the surviving entry; curation never deletes them.

```sql
CREATE TABLE pbook.pbk_entry_sources (
    id                       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    entry_id                 BIGINT NOT NULL
                             REFERENCES pbook.pbk_entries(id) ON DELETE CASCADE,
    session_id               TEXT NOT NULL DEFAULT '',
    project_name             TEXT NOT NULL DEFAULT '',
    experience_hash          TEXT,
    source_context           TEXT NOT NULL DEFAULT '',
    source_context_embedding HALFVEC(1536),
    created_at               TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (entry_id, session_id, experience_hash)
);
```

### `pbk_ingested_sessions`

Ingestion bookkeeping. Rows are **owned by `IngestWorkflow`**: its first activity writes the
`running` row, the workflow-level error handler writes `error`, and the curation sweep flips
rows stuck `running` for more than 48 h to `error` with reason `abandoned`. The CLI never
seeds rows.

```sql
CREATE TABLE pbook.pbk_ingested_sessions (
    session_id        TEXT PRIMARY KEY,
    project_name      TEXT NOT NULL DEFAULT '',
    ingested_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    experiences_found INTEGER NOT NULL DEFAULT 0,
    entries_created   INTEGER NOT NULL DEFAULT 0,
    status            TEXT NOT NULL CHECK (status IN ('running', 'completed', 'error')),
    workflow_id       TEXT,
    run_id            TEXT,
    error_message     TEXT
);
```

### `pbk_retrieval_events`

One row per search, recording what was served so feedback can be attributed. Written
best-effort by `service.search` together with an atomic `retrieval_count` increment.

```sql
CREATE TABLE pbook.pbk_retrieval_events (
    id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    query            TEXT,
    tags             TEXT[],
    mode             TEXT,
    served_entry_ids BIGINT[],
    client           TEXT,
    session_id       TEXT                            -- Claude Code session UUID, if known
);
```

### `pbk_feedback_events`

One row per human-confirmed signal. `session_id` is the **Claude Code session UUID** supplied
by the skill — a distinct namespace from ingestion session ids. The UNIQUE constraint makes
feedback idempotent per session.

```sql
CREATE TABLE pbook.pbk_feedback_events (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    entry_id   BIGINT NOT NULL REFERENCES pbook.pbk_entries(id),
    polarity   TEXT NOT NULL CHECK (polarity IN ('helpful', 'harmful')),
    context    TEXT NOT NULL DEFAULT '',
    source     TEXT CHECK (source IN ('skill', 'human', 'agent')),
    session_id TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (entry_id, session_id, polarity)
);
```

**Counters are aggregates, not the record.** The `helpful_count` / `harmful_count` /
`retrieval_count` columns on `pbk_entries` remain as cheap scoring aggregates; they are bumped
in the same transaction as the corresponding event insert. The event tables are the source of
truth and the audit trail.

Tag queries JOIN `pbk_entry_tags` with OR semantics. Store read helpers re-assemble a `tags`
list onto each returned entry, so consumers see one shape and never a raw column.

## Entry types

Two types: `pitfall` and `curated`. The `api_doc` type is **removed** — it is already absent
from the code, and the CHECK constraint above now rejects it at the schema level.

### Pitfall (`entry_type = "pitfall"`)

Extracted from experience by the LLM. A specific, unexpected situation where the default
approach did not work. Enters life as `probation`.

```json
{
    "title": "Mistral OCR returns base64 with data URI prefix",
    "content": "The image_base64 field includes a 'data:image/jpeg;base64,' prefix. Strip it before calling base64.b64decode() or the prefix gets decoded into garbage bytes prepended to the image data.",
    "tags": ["lib:mistral", "domain:ocr", "project:forge"],
    "entry_type": "pitfall",
    "source_project": "forge",
    "status": "probation"
}
```

### Curated advice (`entry_type = "curated"`)

Submitted by a human via `pbook add`. General best practices or library-specific guidance.
Enters life as `active` (the skill-plus-human flow *is* the review).

```json
{
    "title": "Use from __future__ import annotations with Pydantic",
    "content": "When using Pydantic v2 with forward references, add 'from __future__ import annotations' at the top of every file. This enables PEP 604 union syntax (X | Y) and avoids NameError on forward-referenced types.",
    "tags": ["lang:python", "lib:pydantic"],
    "entry_type": "curated",
    "status": "active"
}
```

## Entry lifecycle

`status ∈ {probation, active, stale, rejected, superseded}`. Transitions live in one pure
function, `lifecycle.transition(current, event) -> EntryStatus | IllegalTransition`, with an
exhaustive `match` + `assert_never`; illegal transitions return `IllegalTransition` rather
than raising. Nothing is ever hard-deleted by workflows — `pbook purge` is an explicit admin
command (see [CLI.md](CLI.md)).

| From | To | Event |
| --- | --- | --- |
| probation | active | human approve (`pbook approve`); first helpful feedback |
| probation | rejected | human reject; validation judge |
| active | stale | staleness trigger; `pbook invalidate` |
| stale | active | human revalidate (`pbook approve` on a stale entry) |
| stale | rejected | human reject from triage |
| active, stale | superseded | consolidation (`superseded_by_id` set, sources reparented) |

`rejected` and `superseded` are terminal.

### Staleness triggers

Staleness is computed by the pure `lifecycle.compute_staleness()` over entry metadata, with
constants in a frozen `StalenessConfig`. The weekly `CurationWorkflow` marks matching entries
`stale`; it never deletes (see [WORKFLOWS.md](WORKFLOWS.md)).

| Trigger | Condition |
| --- | --- |
| Age | Entries with any `lib:`/`project:` tag: 270 days since `max(created_at, last_validated_at, last helpful feedback)`. Pure `lang:`/`domain:` entries: 540 days. |
| Signal | `harmful_count >= 2` AND `harmful_count > helpful_count` |
| Dead weight | `retrieval_count >= 10` with zero helpful feedback |

### Entry-creation statuses

| Path | Initial status |
| --- | --- |
| LLM-extracted (ingestion survivors of the judge) | `probation` |
| Judge failures | `rejected` (`rejected_by = 'validator'`, reason saved) |
| Consolidation survivors | `probation`, counters zeroed |
| Rejected consolidation merges | `rejected` (`rejected_by = 'curation'`; parents untouched) |
| `pbook add` | `active` (or `probation` with `--needs-review`) |

`rejected_by` records who rejected an entry: `validator` (the ingestion judge), `human`
(`pbook reject`), or `curation` (the same judge rejecting a merged candidate during
consolidation).

## Embeddings

- Storage is `HALFVEC(1536)` (half-precision pgvector) for entry embeddings and
  `source_context_embedding`; the HNSW index uses `halfvec_cosine_ops`.
- The model is `text-embedding-3-small`; each entry records `embedding_model` and
  `embedding_dim` so a future model change is detectable per row.
- Embeddings are computed at the I/O edge: inside the save activities
  (`embed_and_save_entries`, `apply_consolidation`) and — for the query vector — inside
  `service.search` when an embedder is configured. No other code path embeds.
- Similarity is computed **in the database** via the `<=>` cosine-distance operator
  (similarity = `1 - distance`), never row-by-row in Python. Filtered ANN queries enable
  `hnsw.iterative_scan` (hence the pgvector ≥ 0.8 preflight).
- A NULL embedding is legal (degraded/no-key writes); such entries still surface through the
  lexical and tag candidate lists.

Candidate generation and the ranking formula live in [WORKFLOWS.md](WORKFLOWS.md); this
document only defines the columns they read.

## Tag system

Tags use `namespace:value` format. Five closed namespaces in two tiers:

| Tier | Namespace | Meaning |
| --- | --- | --- |
| General (cross-project, human-curated) | `lang:` | Programming language |
| General | `lib:` | Library or framework |
| General | `domain:` | Problem domain |
| Extracted (project-specific, LLM-produced) | `project:` | Source project identifier |
| Extracted | `pattern:` | Lesson type, e.g. `failure-pattern`, `retry-pattern` |

The namespaces are closed; **values are open** but pattern-validated
(`^[a-z0-9][a-z0-9-]{0,30}$`) and canonicalized by the pure `normalize_tags()` —
lowercase, strip, alias map (e.g. `postgresql → postgres`, `py → python`).

- CLI write path (`add`, `update`): invalid tags are rejected with error code `tag_invalid`.
- LLM-produced tags are normalized and **never save-failing**: a tag with an invalid namespace
  is dropped and logged; the entry still saves.
- Role: tags are a **ranking boost** and a list/triage filter — never a retrieval gate.
  Zero-tag-overlap entries still surface via the lexical and semantic candidate lists.

## Pydantic models

### PlaybookEntry (write model)

Validated on every write path (`pbook add`, ingestion saves).

| Field | Type | Default | Notes |
| --- | --- | --- | --- |
| `title` | str | required | Short descriptive name |
| `content` | str | required | Lesson text |
| `tags` | list[str] | `[]` | Namespaced tags, normalized before save |
| `entry_type` | EntryType | `curated` | `pitfall` or `curated` |
| `source_project` | str | `""` | Which project submitted this |
| `source_task_id` | str | `""` | Client's task identifier |
| `needs_review` | bool | `False` | Add-time flag only — there is no `needs_review` column. `False` → `status = 'active'`; `True` → `status = 'probation'` |
